本仓库采用「JSON 环境定义 + Bash 激活脚本」的轻量级多环境配置方案，集中管理 Web、API、MCP、PostgreSQL 等服务的连接参数，并通过 `source` 注入环境变量供各子包消费。

## 1. 系统组成

- **环境定义文件**：`environments/*.json`（dev1.json / dev2.json / uat.json），每个文件描述一个环境的端口、URL、数据库连接等元数据，包含 `web`、`api`、`db`、`mcp`、`_meta` 字段。
- **当前环境标记**：`environments/.active`，记录最近一次激活的环境名。
- **环境激活脚本**：`environments/set-env.sh`，读取 `.active` 或命令行参数，解析对应 JSON，构造 `DATABASE_URL` 并 `export` 到当前 shell。
- **一键重启脚本**：`environments/restart-env.sh`，先调用 set-env.sh 激活环境，再清理占用端口的进程、启动 Web/API/MCP 服务并轮询健康检查。
- **运行时校验**：后端在 `packages/api/src/db.ts` 和 `packages/api/drizzle/config.ts` 中强制要求 `DATABASE_URL` 存在，未设置时直接抛错；Web 通过 Vite 的 `process.env.WEB_PORT`/`API_PORT` 注入构建期端口。

## 2. 加载与分层顺序

```
set-env.sh 解析 environments/<env>.json
    → export DATABASE_URL / API_PORT / WEB_PORT / MCP_PORT / DB_PORT
    → 更新 .active 为当前环境名
    → 应用代码直接从 process.env 读取
```

- 无默认值绕过：`DATABASE_URL` 缺失即抛错，禁止隐式 fallback。
- 前端 Vite 代理目标、MCP Server 监听端口均依赖同一组环境变量，保证前后端与服务间一致。

## 3. 关键约定

- 新增环境：复制任一 `*.json`，修改端口与数据库名，写入 `echo <name> > environments/.active`。
- 端口分配规则：同一服务不同环境间隔 ≥ 100（Web: 13181/13281, API: 13180/13280, DB: 5432/5433）。
- AI 行为约束：AI 只读环境 JSON 与 `.active`，可执行 `curl`/`lsof` 验证可达性，但不得编辑配置文件或启停服务。
- Docker Compose 仅用于本地开发时拉起 PostgreSQL，不承载应用进程。

## 4. 开发者应遵循的规则

1. **启动任何服务前必须先激活环境**：`source environments/set-env.sh [env-name]`，否则 `DATABASE_URL` 为空将导致启动失败。
2. **禁止硬编码端口或连接串**：所有端口、URL、DB 连接必须从 `process.env` 读取，由 set-env.sh 注入。
3. **新增环境需同步更新端口表与文档**，确保端口冲突检测有效。
4. **使用 `restart-env.sh` 进行完整重启**，避免残留进程占用端口。
