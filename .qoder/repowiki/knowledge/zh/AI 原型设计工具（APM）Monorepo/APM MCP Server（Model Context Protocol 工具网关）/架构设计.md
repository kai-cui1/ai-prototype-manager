- 入口 `src/index.ts` 使用 `@modelcontextprotocol/sdk` 的 `McpServer` 创建 MCP 服务器，并通过 Express 提供 `/sse`（SSE 连接建立）和 `/messages`（消息转发）两个端点，同时暴露 `/health` 健康检查；端口与后端地址由环境变量 `MCP_PORT`/`API_BASE_URL` 注入。
- 所有对外 HTTP 调用统一经模块内导出的 `callApi(path, options)` 封装：自动拼接 `API_BASE_URL`、处理 204 No Content、并将非 2xx 响应包装为 `{ _error: true, status, ...data }` 供 AI 消费。
- 工具按业务域拆分为 `tools/` 下的独立文件（`project-tools`、`domain-tools`、`organization-tools`、`snapshot-tools`、`process-tools`），每个文件导出一个 `registerXxxTools(server)` 函数，在 `main()` 中集中注册，形成“按领域分文件 + 集中装配”的边界。
- 工具本身是纯被动适配器：不维护会话状态、不做对话编排，仅把 MCP Tool 参数映射到 `/api/v1/projects/:id/...` 等 REST 路径并原样返回 JSON，符合 D-10 被动工具决策。
- `snapshot-tools` 实现 `getProjectSnapshot`，遵循 D-14/D-15 决策：Level 0 返回包含可操作引用（如 roles[].actions[] 带 id/name/inputCount/outputCount）的概要快照，Level 1 支持按 `modules` 参数拉取详细数据。
