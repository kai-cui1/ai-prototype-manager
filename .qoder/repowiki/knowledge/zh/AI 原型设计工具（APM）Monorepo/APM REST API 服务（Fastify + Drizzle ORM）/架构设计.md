模块采用三层分层：`src/routes/` 暴露 Fastify 路由（按功能域拆分为 `projects.ts`、`domain.ts`、`process.ts`、`architecture.ts`、`organization.ts`、`application-behavior.ts`、`role-behavior.ts`、`external-entity-behavior.ts`、`snapshot.ts`），每个路由文件通过 `app.register(routes, { prefix })` 挂载到 `/api/v1/projects/:projectId/...` 前缀下；`src/services/` 实现纯函数式业务逻辑，以 `db: Db` 作为首参数注入，无全局状态依赖，由路由层调用；`src/models/schema.ts` 集中定义 Drizzle pg-core 表结构，`src/db.ts` 导出 `drizzle(sql, { schema })` 实例和 raw `migrationSql` 连接。

入口 `src/app.ts` 统一注册 CORS、@fastify/swagger + @scalar/fastify-api-reference（OpenAPI 3.0.3）、全局错误处理器（将带 `statusCode` 的业务异常映射为 `{ error: { code, message, requestId } }`）、请求耗时 Hook，并在非 VITEST 环境下监听端口。

数据库层使用 drizzle-orm + postgres-js，所有表通过 `project_id` 外键做项目级隔离，自引用 FK（departments、businessArchitectures、menus）用 `@ts-expect-error` 标注循环引用；JSONB 字段（config/actions/decisions/nodeIds/edgeIds 等）承载 UI 元数据与行为定义，避免频繁 DDL 变更。

快照 API（`routes/snapshot.ts` + `services/snapshot.service.ts`）是 Design AI 的入口仪式，按 D-14/D-15 决策支持 Level 0（概要+引用级属性，含 id/name/displayName/inputCount/outputCount 等可操作引用）与 Level 1（按 `modules` 参数按需展开 domain/organization/process/application/architecture 完整详情）。
