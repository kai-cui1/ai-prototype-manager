## Phase 4：下游 Coding AI 集成

> **核心定位**：本系统与下游 Coding AI 打通，输出 PM 在产品和功能规划上的完整结构化信息，最大程度保证信息完整不失真，甚至可用于检查代码实现的完整度。
>
> **当前状态**：仅确定大方向和核心定位，具体任务拆分待后续完善。

### 方向性任务（细节待定）

| # | 方向 | 说明 |
|---|------|------|
| 4.x | 下游 MCP 只读接口实现 | Coding AI 通过 MCP 查询项目完整结构和交互逻辑 |
| 4.x | 结构化输出规格定义 | 按前端功能规格 / 后端功能规格 / 设备交互规格三维度组织输出 |
| 4.x | 实现完整性对照检查 | 原型定义 vs 已实现代码的覆盖度分析，识别遗漏 |
| 4.x | 输出产物打包与分发 | 按消费场景（编码/测试/评审）组织输出内容格式 |

>
> **当前状态**：仅确定大方向和核心定位，具体任务拆分待后续完善。

### 方向性任务（细节待定）

| # | 方向 | 说明 |
|---|------|------|
| 5.x | 上游 Design AI 接入 | Design AI 通过上游 MCP 接口操作原型（读写） |
| 5.x | AI 辅助流程设计 | 自然语言描述 → 自动生成流程图 + 完整性校验 |

## V1 → V2 变更说明

| 变更点 | V1（旧） | V2（新） | 原因 |
|--------|----------|----------|------|
| 阶段命名 | 阶段一~五 | Phase 0~5 | Phase 0 明确表达「设计先行」的定位 |
| Phase 0 范围 | 12/15 任务 | 13/15 任务 | 补充了 workflow.md 完整工作流设计 |
| Phase 1 定位 | 技术验证 | 架构冻结 + MVP | 明确不含 MCP/AI，聚焦可运行的原型系统 |
| Phase 3 定位 | 核心功能实现 | 原型系统成熟度提升 | 重命名以准确反映该阶段的打磨性质 |
| Phase 4 定位 | 自动化能力与输出 | 下游 Coding AI 集成 | 聚焦与下游打通的核心价值 |
| Phase 5 定位 | 完善与打磨 | AI 能力增强 | 聚焦 AI 赋能已有功能 |
| 版本管理位置 | Phase 5.2 | Phase 3.7 | 合并到成熟度提升阶段，避免分散 |
| Phase 4/5 粒度 | 具体任务列表 | 大方向 + 待定 | 当前阶段只需确定定位，细节后续完善 |
| 总任务数 | 37 | ~45 | Phase 1 拆分更细 + Phase 4/5 预留扩展空间 |
