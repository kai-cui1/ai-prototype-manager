# 建设路线图 V4

> 本文档记录 ai-prototype-manager 项目的完整建设计划，按阶段组织。
> **V4 版本**：重构为「工程基础设施（一次性）+ 功能 SDLC 循环（S0~S8）」两层模型。
> **文件结构**：主文件（本文件）+ 各阶段明细（`phase0.md` ~ `phase5.md`）
> 最后更新：2026-05-13

---

## 执行模型说明

### 两层架构

```
┌─────────────────────────────────────────────────────┐
│  Layer 1: 工程基础设施（一次性投入）                   │
│  ─ 技术选型 / 脚手架 / 编码规范 / Design Token       │
│  ─ Phase 0 完成，所有模块复用，不随功能重复           │
│  ─ 部署方案在全部功能完成后统一实施                    │
└──────────────────────────┬──────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────┐
│  Layer 2: 功能 SDLC 循环（每个功能点走一遍 S0~S8）      │
│  ─ F-M1-01, F-M1-02, ... 各自独立走完 9 步            │
│  ─ 进度以「功能 × 阶段」二维矩阵呈现                  │
└─────────────────────────────────────────────────────┘
```

### SDLC 9 步流程（每个功能点必须走完）

| 步骤 | 名称 | 产出物 | 对应 `docs/` 目录 |
|:----:|------|--------|:-----------------:|
| **S0** | 产品思路 & 想法 | 模糊方向、未被详细讨论的 idea | `01-design-idea/` |
| **S1** | 领域模型 & 业务流程设计 | 实体关系、数据流、业务对象属性 | `02-domain-model/` |
| **S2** | PRD 设计 | 功能结构、页面交互逻辑、业务规则 | `03-prd-ux/modules/` |
| **S3** | 高保真原型设计 | HTML 交互原型 + PROTOTYPE-CONTRACT 契约 | `03-prd-ux/prototypes/` |
| **S4** | 技术方案设计 | 技术选型、架构图、DB 设计、API 规范 | `04-tech-design/` + `05-data-design/` |
| **S5** | 测试用例设计 | 测试方案 + 用例集（编码前先写） | `06-test-design/` |
| **S6** | 代码实现 | 具体编程任务（接口/页面级颗粒度） | `packages/` |
| **S7** | 测试代码编写 | API 单元测试 + E2E 测试代码 | `packages/api/tests/` + `packages/e2e/tests/` |
| **S8** | 测试验证执行 | 运行全量测试 → 全绿闭环（Dev-Test Loop） | CI / 本地执行 |

> **执行规则**：框定一个功能点 → 走完 S0~S8 → 再进入下一功能点。允许 S4 提前完成（本项目的实际情况），但 S2（PRD）必须在 S6（编码）之前完成。

### V3 → V4 核心变更

| 变更点 | V3（旧） | V4（新） | 原因 |
|--------|----------|----------|------|
| **SDLC 步骤** | 7 步（Step 0~7） | **9 步（S0~S8）** | 新增 S3 原型设计 + S8 测试验证闭环 |
| **Roadmap 结构** | 4 张重叠表格（SDLC矩阵/功能点/PRD/代码资产） | **1 张主表**（功能 × S0~S8 二维矩阵） | 信息集中，一目了然 |
| **基础设施** | 混在 M1 模块内作为 1-A | **独立为 §1 层（一次性）** | 不随每个功能重复走 |
| **部署方案** | 每个 Step 7 都出现 | **移到最后统一执行** | 属于工程收尾工作 |
| **子功能编号** | 无规则 | **`-xx` 子编码**（如 F-M1-02-01） | 大功能拆分后可独立跟踪进度 |
