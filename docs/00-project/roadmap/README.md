> 本文档记录 ai-prototype-manager 项目的完整建设计划，按阶段组织。
> **V4.2 版本**：重构为「工程基础设施（一次性）+ 功能 SDLC 循环（S0~S7）」两层模型。
> **文件结构**：主文件（本文件）+ 各阶段明细（`phase0.md` ~ `phase5.md`）
> 最后更新：2026-05-26

## 执行模型说明

### 两层架构

```
┌─────────────────────────────────────────────────────┐
│  Layer 1: 工程基础设施（一次性投入）                   │
│  ─ 技术选型 / 脚手架 / 编码规范 / Design Token       │
│  ─ Phase 0 完成，所有模块复用，不随功能重复           │
│  ─ 部署方案在全部功能完成后统一实施                    │
└──────────────────────────┬──────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────┐
│  Layer 2: 功能 SDLC 循环（每个功能点走一遍 S0~S7）      │
│  ─ F-M1-01, F-M1-02, ... 各自独立走完 8 步            │
│  ─ 进度以「功能 × 阶段」二维矩阵呈现                  │
└─────────────────────────────────────────────────────┘
```

### SDLC 8 步流程（每个功能点必须走完）

| 步骤 | 名称 | 产出物 | 对应 `docs/` 目录 |
|:----:|------|--------|:-----------------:|
| **S0** | 产品思路 & 想法 | 模糊方向、未被详细讨论的 idea | `01-design-idea/` |
| **S1** | 领域模型设计 | 领域对象、属性、关系（ER 图）、关键状态图 | `02-domain-model/` |
| **S2** | PRD 设计（纯业务层） | 业务流程、业务规则、功能结构、数据规格 | `03-prd-ux/modules/` |
| **S3** | 交互设计 | 人-系统交互规格 + AI-系统交互规格（页面布局、操作流程） | `03-prd-ux/modules/`（与 PRD 并列） |
| **S4** | 技术方案设计 | 技术选型、架构图、DB 设计、API 规范 | `04-tech-design/` + `05-data-design/` |
| **S5** | 测试用例设计 | 测试方案 + 用例集（编码前先写） | `06-test-design/` |
| **S6** | 代码实现 | 具体编程任务（接口/页面级颗粒度） | `packages/` |
| **S7** | API 测试编写与验证 | API 测试代码 + 全绿闭环（E2E 由人工执行） | `packages/api/tests/` |

> **执行规则**：框定一个功能点 → 走完 S0~S7 → 再进入下一功能点。允许 S4 提前完成（本项目的实际情况），但 S2（PRD）必须在 S6（编码）之前完成。
>
> **E2E 测试策略**（2026-05-26 决策）：E2E 自动化测试跳过，改由人工执行。AI 完成 S6 后通过 browser-agent 截图自检，PM 人工验收。
