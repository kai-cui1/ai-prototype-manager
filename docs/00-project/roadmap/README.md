# 建设路线图 V3

> 本文档记录 ai-prototype-manager 项目的完整建设计划，按阶段组织。
> **V3 版本**：基于实际执行模式重写，反映「模块化 × SDLC 7步」的真实推进方式。
> **文件结构**：主文件（本文件）+ 各阶段明细（`phase0.md` ~ `phase5.md`）
> 最后更新：2026-05-07

## 执行模型说明

### SDLC 7 步流程（每个功能模块必须走完）

| 步骤 | 名称 | 产出物 | 对应 `docs/` 目录 |
|------|------|--------|:-----------------:|
| **0** | 产品思路 & 想法 | 模糊方向、未被详细讨论的 idea | `01-design-idea/` |
| **1** | 领域模型 & 业务流程设计 | 实体关系、数据流、业务对象属性 | `02-domain-model/` |
| **2** | 产品 PRD 设计 | 功能结构、页面交互逻辑、业务规则 | `03-prd/modules/[模块名]/` |
| **3** | 前后端技术方案 | 技术选型、架构图、DB 设计、API 规范 | `04-tech-design/` + `05-data-design/` |
| **4** | 测试用例设计 | 测试方案 + 用例集（编码前先写） | `06-test-design/` |
| **5** | 前后端代码实现 | 具体编程任务 | `packages/` |
| **6** | 单元测试 & 集成测试 | 测试代码 | `packages/` |
| **7** | 部署方案设计 | 部署架构图、环境配置 | `07-deploy-design/` |

> **执行规则**：框定一个模块 → 走完 7 步 → 再进入下一模块。允许 Step 3 提前完成（本项目的实际情况），但 Step 2（PRD）必须在 Step 5（编码）之前完成。

### V2 → V3 核心变更

| 变更点 | V2（旧） | V3（新） | 原因 |
|--------|----------|----------|------|
| **Phase 1 任务模型** | 8 个线性任务 | **基础设施 + 6 模块 × SDLC 7步** | 实际按模块逐个走 SDLC |
| **Phase 1 范围** | 含组件库/HTML引擎/预览 | **仅数据模型中心** | 这些归入 Phase 2 |
| **PRD 工作** | 完全未跟踪 | **Step 2 一等公民**，有进度矩阵 | PRD 是当前核心工作 |
| **基础设施状态** | 全部"待开始"(0%) | **9 项全部完成**(100%) | 反映真实进度 |
| **模块完整性** | 隐含 3 大模块 | **6 个模块**，与 tech design 6 组路由对齐 | 补入 M4 + 菜单 |
