# UI 设计缺口分析：PRD → 前端编码之间缺失的视觉设计环节

> **日期**：2026-05-09
> **触发场景**：M1 Step 5 代码实现完成后，UI 视觉效果差（Sidebar/表格/按钮/间距等"一塌糊涂"）
> **关联问题**：#47 UI 样式全面优化（P1 待处理）

---

## 1. 问题现象

M1 Step 5 编码实施完成（commit `957261c`，70 files, +17395 行），本地服务启动后，前端页面存在以下视觉问题：

- Sidebar 过于简陋，缺少视觉层次
- 主内容区 padding/spacing 不够精致
- 表格样式粗糙
- 按钮、输入框尺寸不统一
- 整体缺乏专业感

**根因不是代码质量问题，而是流程缺失——开发者在没有视觉参考的情况下编写了 UI。**

## 2. 现有流程覆盖范围分析

### 当前 SDLC 各步骤的实际产出物

| 步骤 | 名称 | 实际产出 | 覆盖"长什么样"？ |
|------|------|----------|:---:|
| Step 0 | 产品思路 & 想法 | 模糊方向、idea 记录 | — |
| Step 1 | 领域模型 & 业务流程 | 实体关系、数据流、业务对象属性 | — |
| **Step 2** | **产品 PRD 设计** | **功能结构、页面交互逻辑、业务规则（文字描述）** | **部分：交互逻辑描述了"怎么操作"，但没有视觉呈现** |
| Step 3 | 前后端技术方案 | 技术选型、架构图、DB/API 规范、**编码规范** | **间接：Tailwind 使用规则、shadcn 组件清单、间距规范——但都是"怎么写代码"，不是"长什么样"** |
| Step 4 | 测试用例设计 | 测试方案 + 用例集 | — |
| Step 5 | 代码实现 | 具体编程实现 | — |
| Step 6~7 | 测试 & 部署 | — | — |

### 关键发现

#### 发现 1：`docs/03-prd-ux/prototypes/` 目录为空

CLAUDE.md 明确规定 Step 2 的产出应包含 **HTML 高保真原型**：

> 产品 PRD / 交互原型 → `docs/03-prd-ux/modules/[模块名]/`（按模块分文件夹）
> `prototypes/` 放 HTML 高保真原型

但该目录在 M1 PRD 编写过程中被跳过，没有任何原型文件。

#### 发现 2：技术方案的编码规范 ≠ 视觉设计

`coding-convention-frontend.md`（1209 行）包含大量前端规范：
- Tailwind CSS 使用规范（断点、布局模式、间距 scale）
- shadcn/ui 组件清单和使用指南
- 语义化颜色 token 定义
- 自定义组件变体示例（StatusBadge 等）

但这些规范的定位是 **"开发者写代码时的约束规则"**，而非 **"设计师交付的视觉规格"**。区别在于：

| 维度 | 编码规范（现有） | 视觉设计（缺失） |
|------|-----------------|-----------------|
| 回答的问题 | "代码怎么写？" | "界面长什么样？" |
| 内容示例 | "使用 `space-y-4` 做区域分隔"、"优先使用语义化 token" | "Sidebar 宽度 256px，选中态背景色 #f0f0f0"、"表格行高 44px" |
| 受众 | 开发者 | 开发者 + PM + 未来设计师 |
| 粒度 | class 级别的使用约定 | 页面级/组件级的视觉呈现 |

#### 发现 3：PRD 文字描述无法替代视觉参考

以 M1 项目列表页为例，PRD 描述了：

- ✅ 页面包含哪些区域（搜索栏 + 表格 + 分页器 + 空状态）
- ✅ 每个区域有哪些字段和操作
- ✅ 交互逻辑（搜索防抖 300ms、归档确认弹窗等）

但 PRD **没有描述**：

- ❌ Sidebar 和主内容区的比例
- ❌ 表格列宽分配
- ❌ 操作按钮是文字按钮还是图标按钮
- ❌ 空状态的图标和文案排版
- ❌ 整体配色氛围（冷色调/暖色调？）

这些视觉决策在 Step 5 编码时由开发者"自由发挥"，导致风格不一致。

## 3. 缺失环节的具体定义

### 缺失的是什么？

从 **产品意图** 到 **可运行的像素级界面** 之间，缺少一个 **"视觉设计"** 层：

```
Step 2 PRD（功能规格："做什么"+"怎么交互"）
    ↓
   ??? ← 【缺失】视觉设计（"长什么样"）
    ↓
Step 5 代码实现（用代码还原视觉设计）
```

### 缺失层应包含的内容

| 内容项 | 说明 | 示例 |
|--------|------|------|
| **全局设计语言** | 配色方案、字体层级、圆角/阴影体系、间距节奏 | 主色 #3b82f6、标题 20px bold、卡片圆角 8px |
| **布局规格** | 页面栅格系统、响应式断点行为、容器最大宽度 | 主内容区 max-width 1200px、Sidebar 固定 256px |
| **组件视觉规格** | 每个自定义组件的具体外观 | StatusBadge active=绿底绿字、表格行 hover 背景 |
| **页面线框图/原型** | 关键页面的布局草图或 HTML 原型 | 项目列表页、项目详情页、创建弹窗 |

## 4. 影响评估

### 已造成的影响

| 影响 | 具体表现 |
|------|---------|
| UI 质量不可控 | 开发者自由发挥导致风格混乱，需要返工优化（#47） |
| 效率低下 | 先写出"能跑"的 UI，再花时间打磨，不如一开始就有参考 |
| 决策分散 | 本应由设计阶段统一决策的视觉细节，散落在各组件代码中 |
| 可维护性差 | 后续修改 UI 时缺乏统一依据，容易改一处乱一处 |

### 如果不补上的长期风险

- 每个 Phase/模块都会重复出现"先写后磨"的低效循环
- 不同模块之间 UI 风格可能不一致（不同开发者/不同时间的审美差异）
- 未来引入设计师时，没有设计资产可以继承
