### 测试数据准备说明

E2E 测试通过浏览器操作 UI，前置条件中的"已有数据"指**页面上可见的数据状态**：

| 数据标识 | 页面可见状态 |
|---------|------------|
| 活跃项目详情 | 详情页显示一个 status=active 的项目完整信息 |
| 已归档项目详情 | 详情页显示一个 status=archived 的项目信息 |
| 有子模块数据的项目 | 详情页概要卡片区域显示非零统计数 |

## 正常流程

### TC-E2E-M1-03-001 进入活跃项目详情页 — 完整页面渲染

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-03-001 |
| **用例名称** | 详情页渲染 — 活跃项目的顶部栏 + 基本信息卡 + 模块概要卡片 + 组织管理区域全部正确展示 |
| **对应AC** | AC-M1-07, B-M1-14, B-M1-17（时间戳格式化） |
| **优先级** | P0 |
| **前置条件** | 从列表页点击名为"换电站管理系统"的活跃项目行；或直接导航到该项目的详情页 URL |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 等待页面加载完成（Skeleton 消失） | 页面渲染完成，无 Skeleton、无空状态、无 Error Boundary |
| 2 | 观察顶部栏 | 面包屑显示"首页 > 项目 > 换电站管理系统"；右侧有绿色"活跃"Badge；有「编辑」按钮（次要样式）和「归档」按钮（危险/红色样式） |
| 3 | 观察基本信息卡 | 显示：name=`charging-station-mms`（小字标注）、display_name=`换电站管理系统`、description=项目描述文本（如有）、version=`v1`、created_at 和 updated_at 时间格式为 `YYYY-MM-DD HH:mm` |
| 4 | 观察模块概要卡片区域 | 显示 2~4 列卡片网格：领域模型 / 业务流程 / 组织架构 / 外部实体（外部实体可能因 P1 而不存在）；每张卡片含图标+标题+统计数+N 个入口箭头 |
| 5 | 观察组织管理区域 | 区域标题"业务参与方（组织架构）"；浅色说明文案框；公司列表（可能有数据也可能为空提示）；「新建公司」按钮 |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 面包屑 | 等于 `"首页 > 项目 > 换电站管理系统"` |
| 项目标题 | 等于 `"换电站管理系统"`，后面附 name 小字标注 |
| 状态 Badge | 绿色背景 + 白色文字"活跃" |
| 编辑按钮 | 可见且可点击（非禁用态） |
| 归档按钮 | 可见且可点击（红色/危险样式） |
| description 字段 | 有值时显示文本内容；无值时显示 `"—"` |
| version 格式 | 以 `v` 开头后跟数字（如 `v1`） |
| 时间戳格式 | 符合 `YYYY-MM-DD HH:mm` 格式（B-M1-17），非 ISO 8601 原始格式 |
| 概要卡片数量 | ≥ 3 张（领域模型 + 业务流程 + 组织架构至少存在） |
| 统计数字 | 每张卡片上的数字为整数（可为 0） |

### TC-E2E-M1-03-002 并行请求验证 — 详情和摘要同时加载

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-03-002 |
| **用例名称** | 并行请求 — 验证详情和摘要两个 API 请求并行发起（非串行） |
| **对应AC** | B-M1-16（两个请求并行发起） |
| **优先级** | P1 |
| **前置条件** | 导航到某活跃项目详情页；开启网络请求监控（Playwright route 监听） |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 导航到 `/projects/{id}` | 页面开始加载 |
| 2 | 监控发出的网络请求 | 同时（或几乎同时）发出两个 GET 请求：`GET /api/v1/projects/{id}` 和 `GET /api/v1/projects/{id}/summary` |
| 3 | 观察请求时序 | 两个请求的发起时间差 < 50ms（即不是等第一个返回后再发第二个） |
| 4 | 等待两个响应都返回 | Skeleton 消失；页面完整渲染 |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 请求数量 | 页面加载期间恰好发出 2 个 GET 请求（detail + summary） |
| 请求并行性 | 两个请求几乎同时发起（非串行） |
| 总耗时 | ≤ max(详情耗时, 摘要耗时) + 少量渲染开销（而非两者之和） |
