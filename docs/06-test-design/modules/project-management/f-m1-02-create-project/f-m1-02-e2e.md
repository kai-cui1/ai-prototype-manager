| 数据标识 | 页面可见状态 |

## 正常流程

### TC-E2E-M1-02-001 创建项目 — 完整流程（全字段 + 成功后自动跳转详情）

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-02-001 |
| **用例名称** | 创建项目 — 填写全部字段，提交成功后 Toast 提示并自动跳转详情页 |
| **对应AC** | AC-M1-06, B-M1-12（创建后行为：Toast+跳转） |
| **优先级** | P0 |
| **前置条件** | 已在项目列表页；PM 用户已登录；DB 中无 name=`my-new-project` 的项目 |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 点击页面顶部「新建项目」按钮 | 弹出居中 Dialog，标题为"新建项目"；包含 name 输入框、display_name 输入框、description 文本域、底部「取消」+「确认创建」按钮 |
| 2 | 在 name 输入框输入 `my-new-project` | 输入框显示输入值；下方无错误提示（格式合法） |
| 3 | 在 display_name 输入框输入 `我的新项目` | 输入框显示输入值；下方无错误提示 |
| 4 | 在 description 文本域输入 `这是一个测试项目描述` | 文本域显示输入值 |
| 5 | 点击「确认创建」按钮 | 按钮进入 loading 态（spinner + 禁用点击）；Dialog 保持打开 |
| 6 | 等待网络请求完成（loading 消失） | Dialog 关闭；页面出现成功 Toast："项目「我的新项目」创建成功"；页面自动导航到 `/projects/{new-id}` 详情页 |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 当前 URL | 为 `/projects/{新创建项目的 UUID}` 格式（非列表页） |
| 详情页标题/面包屑 | 显示"首页 > 项目 > 我的新项目" |
| 详情页项目名称 | 等于 `"我的新项目"` |
| 详情页 name 标注 | 显示小字 `my-new-project` |
| 详情页状态 Badge | 显示绿色"活跃"标签 |
| Toast 提示 | 出现且文案包含"创建成功"和项目显示名称（数秒后自动消失） |
| 列表页状态 | 不再是当前页面（已跳转离开） |

**备注**: 验证 B-M1-12（创建后必须 Toast + 自动跳转详情页，不停留在列表页）。

### TC-E2E-M1-02-004 name 格式错误 — 前端即时校验（失焦触发）

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-02-004 |
| **用例名称** | name 校验 — 输入非法格式（大写字母/数字开头/特殊字符），失焦后显示字段级错误 |
| **对应AC** | AC-M1-04, B-M1-10（前端即时校验部分） |
| **优先级** | P0 |
| **前置条件** | 创建项目 Dialog 已打开 |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 在 name 输入框输入 `InvalidName`（含大写字母） | 输入框显示输入值；暂无错误（等待失焦） |
| 2 | 点击 display_name 输入框使 name 失焦 | name 输入框下方立即出现红色错误提示，文案包含"格式""小写""字母开头"等关键词之一 |
| 3 | 清空 name 并输入 `1-starts-with-number`（数字开头） | 输入框显示新值 |
| 4 | 点击 display_name 使 name 再次失焦 | 错误提示更新为新的格式错误信息 |
| 5 | 清空 name 并输入 `bad@name`（非法特殊字符） | 输入框显示新值 |
| 6 | 点击 display_name 使 name 再次失焦 | 错误提示再次更新 |
| 7 | 修正 name 为 `valid-name-format`（合法格式） | 输入框显示合法值 |
| 8 | 点击 display_name 使 name 失焦 | name 下方的红色错误提示**消失** |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 失焦后错误显示延迟 | 即时显示（< 200ms），无需点击提交按钮 |
| 错误提示位置 | 在 name 输入框正下方（字段级定位） |
| 错误提示样式 | 红色文字（error 态） |
| 修正后错误消失 | 输入合法值并失焦后，之前的错误提示清除 |
| 「确认创建」按钮 | 有错误时仍可点击（前端不阻止提交，最终由后端兜底校验）；或按实现可为禁用态（以实际为准） |

### TC-E2E-M1-02-008 取消/关闭弹窗 — 三种方式均丢弃输入

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-02-008 |
| **用例名称** | 取消创建 — 点击取消按钮 / 按 Esc / 点击遮罩，三种方式均关闭弹窗且不保存 |
| **对应AC** | §4.2.4.7 异常场景 #5（用户中途关闭弹窗）, UI-M1-06 |
| **优先级** | P1 |
| **前置条件** | 创建项目 Dialog 已打开；已在 name 填入 `will-be-discarded`，display_name 填入 `将被丢弃` |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | （变体 A）点击「取消」按钮 | Dialog 立即关闭；遮罩消失；返回列表页 |
| 2 | 重新打开 Dialog，填写相同内容 | Dialog 中字段有值 |
| 3 | （变体 B）按 Esc 键 | Dialog 关闭；效果同变体 A |
| 4 | 重新打开 Dialog，填写相同内容 | Dialog 中字段有值 |
| 5 | （变体 C）点击 Dialog 外部半透明遮罩区域 | Dialog 关闭；效果同上 |
| 6 | 观察列表页 | 列表中**没有**新增名为"将被丢弃"的项目（输入确实被丢弃） |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 三种关闭方式一致性 | 取消按钮 / Esc / 遮罩点击 效果一致：关闭弹窗 + 不保存 |
| 关闭后数据不保留 | 列表页无新项目；重新打开 Dialog 时字段为空（不暂存草稿，§4.2.4.7） |
| 关闭速度 | 立即关闭，无 loading 或二次确认 |

| 5 | 点击「重试」（此时 500 触发已解除） | 请求成功；Dialog 关闭；Toast → 跳转详情页 |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 500 时 Dialog 不关闭 | 与 409 一致：保留用户输入以便修正或重试 |
| 错误提示文案 | 通用友好中文（如"服务器繁忙，请稍后重试"），**不包含**技术细节（无异常类名、无堆栈） |
| 与 409 的区别 | 409 错误定位到 name 字段下方；500 错误为 Dialog 级别的通用提示（非字段级） |

### TC-E2E-M1-02-012 提交时表单完整校验 — 多字段同时报错

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-02-012 |
| **用例名称** | 完整校验 — 不填写任何字段直接点击提交，验证聚焦到第一个错误字段 + 多错误同时展示 |
| **对应AC** | AC-M1-04（name 必填 + 格式校验）, B-M1-21（display_name 必填） |
| **优先级** | P0 |
| **前置条件** | 创建项目 Dialog 已打开；所有字段均为空 |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 不填写任何字段，直接点击「确认创建」按钮 | 触发表单完整校验 |
| 2 | 观察校验结果 | name 和 display_name 字段下方**同时**出现红色错误提示（name 提示格式/必填，display_name 提示必填） |
| 3 | 观察焦点行为 | 浏览器焦点自动移动到第一个错误字段（通常是 name 输入框） |
| 4 | 仅修正 name 为 `now-valid` | name 下方错误消失；display_name 错误仍存在 |
| 5 | 再次点击「确认创建」 | 仅 display_name 报错；焦点移到 display_name |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 多错误同时展示 | 不是只显示第一个错误就停止，而是所有未通过字段都显示错误 |
| 焦点定位 | 自动聚焦到第一个错误字段（提升用户体验） |
| 逐个修正支持 | 修正一个字段后再次提交，剩余错误仍正确展示 |
| 未通过不发送 API | 前端校验不通过时不发起 POST 请求（减少无效网络请求） |
