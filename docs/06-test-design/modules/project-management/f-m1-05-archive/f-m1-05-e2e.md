# 归档/恢复项目 — E2E 测试用例

> 功能点: **F-M1-05** | 优先级: **P0**
> 对应 PRD: `docs/03-prd/modules/project-management/project-management-prd-2.md` §4.5

---

## 公共上下文

| 项 | 值 |
|----|-----|
| 起始页面 | 项目详情页 `/projects/:id` |
| 用户角色 | PM（项目经理） |
| 浏览器 | Chromium（Playwright） |
| 视口尺寸 | 1280 x 720 |
| 语言 | 中文（zh-CN） |

### 测试数据准备说明

E2E 测试通过浏览器操作 UI，前置条件中的"已有数据"指**页面上可见的数据状态**：

| 数据标识 | 页面可见状态 |
|---------|------------|
| 活跃项目详情 | 详情页显示 status=active 的项目，顶部有红色「归档」按钮 |
| 已归档项目详情 | 详情页显示 status=archived 的项目，顶部有「恢复」按钮（无归档按钮），有灰色「已归档」Badge |

## 正常流程

### TC-E2E-M1-05-001 归档项目 — 完整流程（弹窗→确认→Badge切换→按钮替换）

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-05-001 |
| **用例名称** | 归档 — 活跃项目点击归档→确认弹窗→确认执行→UI 状态全面切换 |
| **对应AC** | AC-M1-12, AC-M1-13, B-M1-09（归档后 UI 反馈）, UI-M1-01, UI-M1-02 |
| **优先级** | P0 |
| **前置条件** | 已在活跃项目详情页；顶部栏显示绿色"活跃"Badge 和红色「归档」按钮 |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 点击顶部栏红色「归档」按钮 | 弹出 AlertDialog：标题"确认归档"；正文含项目名+"该项目及其所有子数据将不可编辑"；红色警告强调文字；红色「确认」按钮 + 「取消」按钮 |
| 2 | 阅读警告文案，点击红色「确认」按钮 | 弹窗关闭；按钮短暂 loading 态（spinner + 禁用）；详情页数据刷新 |
| 3 | 观察顶部栏变化 | 绿色"活跃"Badge 消失，替换为灰色「已归档」Badge；「归档」按钮消失，替换为「恢复」按钮（主样式）；「编辑」按钮消失或禁用 |
| 4 | 观察 Toast 提示 | 出现 Toast："项目「XXX」已归档"（数秒后自动消失） |
| 5 | 观察基本信息卡 | 数据仍正常显示（归档 ≠ 删除，字段不被清空） |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 确认弹窗类型 | AlertDialog 样式（红色确认按钮 + 警告图标）（UI-M1-01） |
| 归档后 Badge | 灰色"已归档"标签（AC-M1-13） |
| 归档后操作按钮 | 「归档」→「恢复」（按钮替换，非消失）；「编辑」隐藏（AC-M1-13） |
| Toast 提示 | 文案包含"已归档"和项目名 |
| 按钮 loading | 确认点击后 spinner + 禁用（UI-M1-02） |
| 子数据可见性 | 组织管理区域的公司列表等仍可见（B-M1-25：不级联删除） |

### TC-E2E-M1-05-002 恢复项目 — 完整流程（弹窗→确认→Badge移除→按钮还原）

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-05-002 |
| **用例名称** | 恢复 — 已归档项目点击恢复→确认弹窗→确认执行→UI 还原为活跃状态 |
| **对应AC** | AC-M1-14, B-M1-12（Toast+状态反馈） |
| **优先级** | P0 |
| **前置条件** | 已在已归档项目详情页；顶部栏显示灰色「已归档」Badge 和「恢复」按钮（无归档/编辑按钮） |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 点击「恢复」按钮 | 弹出确认 Dialog：标题"确认恢复"；正文说明恢复后项目将重新可编辑；主样式「确认」按钮 + 「取消」按钮（注意：恢复不是破坏性操作，确认按钮可能非红色——以实现为准） |
| 2 | 点击「确认」按钮 | 弹窗关闭；按钮 loading 态；详情页刷新 |
| 3 | 观察顶部栏变化 | 「已归档」Badge 消失，替换为绿色"活跃"Badge；「恢复」按钮替换为红色「归档」按钮；「编辑」按钮重新出现 |
| 4 | 观察 Toast | 出现 Toast："项目「XXX」已恢复" |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 恢复后 Badge | 绿色"活跃"标签 |
| 恢复后操作按钮 | 「归档」+「编辑」按钮均恢复可见 |
| Toast 文案 | 包含"已恢复"和项目名 |
| 编辑入口恢复 | name / display_name 字段可重新点击进入编辑模式 |

### TC-E2E-M1-05-003 归档确认弹窗 — 取消操作（三种方式）

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-05-003 |
| **用例名称** | 取消归档 — 弹出确认弹窗后点击取消 / 按 Esc / 点击遮罩，三种方式均关闭弹窗且不执行归档 |
| **对应AC** | UI-M1-06 |
| **优先级** | P1 |
| **前置条件** | 已在活跃项目详情页 |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 点击「归档」按钮弹出确认弹窗 | AlertDialog 显示 |
| 2 | （变体 A）点击「取消」按钮 | 弹窗立即关闭；项目仍为活跃状态；Badge 仍为绿色"活跃" |
| 3 | 再次打开归档弹窗，（变体 B）按 Esc 键 | 弹窗关闭；效果同变体 A |
| 4 | 再次打开归档弹窗，（变体 C）点击遮罩半透明区域 | 弹窗关闭；效果同上 |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 三种方式一致性 | 取消 / Esc / 遮罩点击 效果一致（UI-M1-06） |
| 取消后状态不变 | 项目仍为 active，无任何数据变更 |
| 可重复打开 | 取消后再次点击「归档」仍能正常弹出弹窗 |

### TC-E2E-M1-05-004 乐观锁冲突 — 版本冲突提示 + 刷新页面

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-05-004 |
| **用例名称** | 版本冲突 — 归档期间他人已修改同一项目，提交时返回 VERSION_CONFLICT |
| **对应AC** | G-M1-07, §4.5.4.7 VERSION_CONFLICT, §4.5.3 步骤 6 |
| **优先级** | P0 |
| **前置条件** | 已在活跃项目详情页；通过测试手段模拟 version 不匹配（如另一标签页先执行了编辑使 version 变更） |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 点击「归档」按钮 → 弹出确认弹窗 | 正常弹出 |
| 2 | 点击「确认」按钮 | 按钮 loading → 返回 409 VERSION_CONFLICT |
| 3 | 观察前端处理 | 弹出提示（Toast 或 Alert）："数据已被修改，请刷新重试"；归档弹窗已关闭 |
| 4 | 按提示刷新页面 | 页面重新加载最新数据；项目状态保持原状（未被归档） |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 冲突提示文案 | 用户友好中文，包含"已被修改""刷新""重试"语义 |
| 冲突后状态 | 项目保持原 active 状态（归档未执行） |
| 刷新行为 | 用户可手动或自动刷新获取最新数据 |

### TC-E2E-M1-05-005 网络异常 — 归档请求超时/断网

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-05-005 |
| **用例名称** | 网络异常 — 归档确认后断网，弹窗内/页面上显示错误和重试 |
| **对应AC** | G-M1-10, UI-M1-02 |
| **优先级** | P1 |
| **前置条件** | 已在活跃项目详情页；通过 Playwright 模拟离线 |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 点击「归档」→ 弹出确认弹窗 | 正常弹出 |
| 2 | 模拟网络离线（setOffline(true)） | 当前状态不变 |
| 3 | 点击「确认」按钮 | 按钮 loading 态 |
| 4 | 等待超时 | loading 结束；弹窗内或页面显示错误提示（含「重试」按钮） |
| 5 | 观察项目状态 | 仍为活跃（未归档） |
| 6 | 点击「重试」按钮 | 按钮 loading 态 |
| 7 | 模拟网络恢复（setOffline(false)） | 重试成功；弹窗关闭；Toast；Badge 变灰；按钮替换 |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 超时后弹窗可能关闭 | 以实现为准（可能在弹窗内显示错误，也可能关闭弹窗后在页面显示） |
| 重试可用 | 网络恢复后重试能成功完成归档 |
| 失败时状态不变 | 项目保持 active |

### TC-E2E-M1-05-007 归档后列表联动 — 列表页数据同步更新

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-05-007 |
| **用例名称** | 列表联动 — 在详情页归档项目后，切回列表页验证归档项目从活跃视图消失 |
| **对应AC** | AC-M1-13, §4.5.6 AI 提示（列表页联动） |
| **优先级** | P1 |
| **前置条件** | 已在活跃项目详情页；该项目的列表页已在另一个标签页打开（或可通过面包屑导航返回） |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 在详情页完成归档操作 | 详情页显示已归档状态 |
| 2 | 点击面包屑「项目」导航回列表页 | 列表页加载 |
| 3 | 观察"全部"视图（默认） | 归档项目可能仍在列表中但 Badge 为灰色（以实现为准：默认视图是否包含归档项目） |
| 4 | 切换到"活跃"Tag 筛选 | 归档项目**不出现**在活跃列表中 |
| 5 | 切换到"已归档"Tag 筛选 | 归档项目**出现**在此视图中，Badge 为灰色"已归档" |

**最终断言**:

| 断言项 | 预期 |
|--------|------|
| 活跃视图不含该项目 | 切换到"活跃"筛选后看不到刚归档的项目 |
| 归档视图含该项目 | 切换到"已归档"筛选能看到该项目 |
| 列表数据一致性 | 列表页数据与详情页归档操作后的状态同步（§4.5.6 AI 提示的 query client 失效等机制生效） |

### TC-E2E-M1-05-008 恢复后列表联动 — 从归档视图回到活跃视图

| 字段 | 内容 |
|------|------|
| **用例ID** | TC-E2E-M1-05-008 |
| **用例名称** | 列表联动 — 在详情页恢复项目后，切回列表页验证项目回到活跃视图 |
| **对应AC** | 补充覆盖 |
| **优先级** | P1 |
| **前置条件** | 已在已归档项目详情页 |

**操作步骤**:

| 步骤 | 操作 | 页面预期 |
|------|------|---------|
| 1 | 在详情页完成恢复操作 | 详情页显示活跃状态 |
| 2 | 导航回列表页 | 列表页加载 |
| 3 | 观察"活跃"视图 | 恢复的项目出现在活跃列表中，Badge 为绿色"活跃" |

| 断言项 | 预期 |
|--------|------|
