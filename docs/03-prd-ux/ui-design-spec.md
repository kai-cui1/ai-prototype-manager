## 0. 设计定位与原则

### 0.1 产品定位

APM 是一个**管理型后台系统**（非 2C 商业产品），面向产品经理和开发者使用。

### 0.2 设计风格参考

以 **Ant Design Pro** 为基准，做以下调整：

| 维度 | Ant Design Pro 默认 | APM 调整 |
|------|---------------------|---------|
| 主色调 | 蓝色 `#1677ff` | 青绿色 `#08979c`（技术感） |
| 圆角 | 小圆角 4px | 中等圆角（按钮 6px / 卡片 8px） |
| 阴影 | 无或极浅 | 轻投影（增加层次感） |
| 字体 | 系统字体栈 | 系统字体栈（一致） |

### 0.3 核心设计原则

1. **信息密度适中** — 不追求极简留白，保证单屏展示足够信息量
2. **专业优先于美观** — 功能清晰 > 视觉惊艳，但整体必须专业协调
3. **一致性高于个性** — 全局统一风格，不因页面而异
4. **暗色模式一等公民** — 不是事后补丁，从设计之初就支持

## 1. 布局系统

### 1.1 整体布局结构

采用 **经典 ADP 三段式布局**：深色侧边栏 + 白色顶栏 + 内容区。

```
┌──────────────────────────────────────────────────┐
│  Header（顶栏，48px 高，白色背景）                  │
├─────────┬────────────────────────────────────────┤
│         │                                        │
│ Sidebar │  Content Area                          │
│ （深色） │  （浅灰背景 #f5f5f5）                    │
│ 220px   │                                        │
│ 可折叠   │  ┌─ Breadcrumb 面包屑                   │
│ 至 64px  │  ├─ Page Title 页面标题                 │
│         │  ├─ Content Card 内容卡片               │
│         │  └─ ...                                 │
│         │                                        │
└─────────┴────────────────────────────────────────┘
```

### 1.2 各区域尺寸规范

| 区域 | 属性 | 值 |
|------|------|-----|
| **Header（顶栏）** | 高度 | `48px` |
| | 背景 | `#fff` |
| | 底部边框 | `1px solid #f0f0f0` |
| | 内边距 | 水平 `24px` |
| **Sidebar（侧边栏）** | 展开宽度 | `220px` |
| | 折叠宽度 | `64px` |
| | 背景 | `#001529`（深色） |
| | 文字颜色 | 默认 `rgba(255,255,255,0.65)`；选中/悬浮 `#fff` |
| | 选中态背景 | `#08979c`（主色） |
| | 悬浮态背景 | `rgba(255,255,255,0.08)` |
| | 菜单项高度 | `40px` |
| | 菜单项内边距 | 水平 `20px` |
| | Logo 区域高度 | `48px` |
| **Content Area（内容区）** | 背景 | `#f5f5f5` |
| | 内边距 | `24px` |

| **Breadcrumb（面包屑）** | 高度 | 自适应 |

### 1.3 响应式断点

| 断点 | 最小宽度 | 行为 |
|------|---------|------|
| 默认 | `0px` | 移动端（Sidebar 抽屉式） |
| `sm` | `640px` | 大手机 / 小平板 |
| `md` | `768px` | 平板（Sidebar 可折叠） |
| `lg` | `1024px` | 小桌面（默认完整布局） |
| `xl` | `1280px` | 大桌面 |

**Phase 1 优先级**：主要适配 `lg` 以上（桌面端），移动端后续迭代。

## 3. 字体与排版

### 3.1 字体栈

```css
font-family: -apple-system, 'PingFang SC', 'Microsoft YaHei', 'Helvetica Neue', sans-serif;
```

**不引入外部字体**。零网络依赖，原生渲染最佳。

### 3.2 字号层级

| 层级 | 字号 | 字重 | 行高 | 用途 |
|------|------|------|------|------|
| **H1 页面标题** | `20px` | `600` | `1.4` | 页面主标题（如"项目管理"） |
| **H2 区块标题** | `16px` | `600` | `1.5` | 卡片内标题、区块名 |
| **H3 子标题** | `14px` | `500` | `1.5` | 表格列头、表单 label |
| **Body 正文** | `14px` | `400` | `1.6` | 主要文本内容 |
| **Body Small** | `13px` | `400` | `1.6` | 次要正文、描述文字 |
| **Caption 辅助** | `12px` | `400` | `1.5` | 时间戳、辅助说明、placeholder |
| **Code/数据** | `13px` | `400` | `1.5` | 代码片段、标识符、数字（等宽感） |

### 3.3 排版间距规则

| 规则 | 值 | 说明 |
|------|-----|------|
| 段落间距 | `16px` (`gap-4`) | 同级元素之间 |

#### 6.3.1 列宽策略（项目级统一规则）

本项目所有列表表格的列宽遵循以下 **4 条铁律**：

| # | 规则 | 说明 |
|---|------|------|
| **1** | **内容自适应，零留白** | 列宽由内容驱动（`table-layout: auto` + `width: auto`），不强制表格撑满容器。短内容列不分配多余空间 |
| **2** | **最大宽度约束 + 省略号 + Tooltip** | 每列定义 `max-width`。内容超出时显示 `...`，鼠标移入显示完整内容（`title` 或 Tooltip 组件） |
| **3** | **拖拽调整列宽** | 鼠标移至列边界（±5px 区域）光标变为 `col-resize`，按住拖动可自由调整该列宽度。调整后变为固定 `px` 宽度 |
| **4** | **双击重置列宽** | 在列边界处双击 → 移除该列的手动宽度 → 恢复为规则 1+2 的自适应布局 |

**各列 max-width 参考值**（根据常见内容长度设定，具体按实际业务调整）：

| 内容类型 | 典型 max-width | 说明 |
|---------|---------------|------|
| 名称 / 标题类 | `200~300px` | 最常超长的列，给足够空间但不无限 |
| 标识符 / Code 类 | `140~180px` | 等宽字体，通常较短 |
| 状态 Badge | `70~90px` | 固定宽度标签 |
| 版本号 | `70~90px` | "v1" / "v2.1" 极短，但需容纳列头文字+排序箭头 |
| 时间戳 | `160~190px` | "2026-05-09 10:30" 格式固定 |
| 操作按钮组 | `100~140px` | "编辑 / 删除" 等 2-3 个链接 |
| 数量 / 计数 | `60~80px` | 数字类 |

> **注意**：以上为参考值。每个模块的 PRD 应根据实际数据特征定义每列的具体 max-width。原型阶段可先用估算值，编码前在技术方案中精确化。

#### 6.3.2 列宽拖拽交互规格

```
┌──────────────────────────────────────────────────────┐
│  正常态：鼠标在普通区域 → 默认光标                      │
│                                                      │
│  悬停态：鼠标靠近列边界(±5px) → 光标变为 ↔ (col-resize) │
│         列边界右侧显示一条竖线高亮提示                    │
│                                                      │
│  拖拽中：跟随鼠标移动实时预览新宽度                       │
│         其他列自动压缩以腾出空间                         │
│         释放后该列锁定为新宽度                           │
│                                                      │
│  双击：移除该列 inline width → 回到自适应                │
└──────────────────────────────────────────────────────┘
```

> **本项目统一标准**：所有列表页的分页组件必须遵循以下规格。

#### 6.7.1 布局结构

```
┌──────────────────────────────────────────────────────────────────────┐
│ 共 87 条记录    [20 条/页 ▾]  │ [<] [1] [2] [3] [4] [5] [>]  │ 跳至 [_] 页 │
```

**从左到右的元素顺序（固定）**：

| # | 元素 | 说明 |

| **2** | pageSize 选择器 | `<select>` 下拉框，选项见下方 §6.7.2 |
| **3** | 分隔线 | 竖线 `1px × 20px`，颜色 `--color-divider` |

#### 6.7.3 页码按钮组

| 属性 | 规格 |

#### 6.7.5 分页交互行为（原型标注用）

## 10. 动效规范

### 10.1 原则

动效服务于功能理解，不为了炫技。遵循：
- **快速**：过渡时间 ≤ 300ms
- **自然**：使用 ease-out 缓动
- **可关闭**：尊重 `prefers-reduced-motion`

### 10.2 常用过渡

| 交互 | 时长 | 缓动函数 | 说明 |
|------|------|---------|------|
| **颜色变化** | `150ms` | `ease` | 按钮 hover、链接变色 |
| **展开/收起** | `200ms` | `ease-in-out` | Accordion、下拉菜单 |
| **淡入/淡出** | `200ms` | `ease` | Toast 出现/消失 |
| **滑动** | `250ms` | `ease-out` | Drawer/Sidebar 展开 |
| **缩放** | `150ms` | `ease` | Tooltip 出现 |

## 11. 高保真原型设计规范（HTML 原型）

> **本节为 M1 模块原型自查与 PRD 交叉审查后的经验总结。每次创建新模块的高保真原型时必须参考。**

### 11.1 原型定位：路线 A — 视觉规格原型

**核心决策**：APM 的高保真 HTML 原型采用**视觉规格原型**路线，而非完整交互模拟 Demo。

**为什么不做完整交互模拟（路线 B）？**

| 维度 | 路线 A（视觉规格） | 路线 B（交互模拟） |
|------|-------------------|-------------------|
| 定位 | UI 设计规范的**可视化实例** | 接近可运行的 Demo |
| 回答的问题 | "长什么样？" | "怎么用？" |
| 开发量 | 小（单文件 HTML） | 大（接近真实前端 30-50%） |
| 维护成本 | 低 | 高（PRD 改动需同步更新） |
| 风险 | 无 | 容易和真实前端代码产生分歧 |

**理由**：
1. APM 是管理后台系统，交互复杂度中等，**视觉一致性比交互炫技更重要**
2. PRD 文档已完整定义了所有交互行为细节，原型不需要重复这份工作
3. 原型的核心价值是**填补"文字 PRD → 代码实现"之间的视觉鸿沟**

### 11.2 职责边界

#### 11.2.0 JS 作用域铁律（最高优先级）

> **高保真原型中的 JavaScript 仅用于"让静态页面可被人类观察和验证"，不用于实现产品功能。**

| 允许的 JS 用途 | 示例 | 理由 |
|---------------|------|------|
| **暗/亮模式切换** | `data-theme` 属性切换 + localStorage 持久化 | 验证两种模式下的视觉呈现 |
| **Tab 切换**（纯显示隐藏） | `display:none/block` 切换内容区 | 验证 Tab 内容布局是否正确 |
| **弹窗打开/关闭** | `classList.add/remove('show')` | 验证弹窗样式、位置、层级 |
| **Toast 提示演示** | `createElement + setTimeout remove` | 验证 Toast 组件外观和位置 |
| **空状态切换演示** | 控制台调用 `toggleEmptyState()` | 验证空状态组件形态 |
| **表单基础校验演示** | 非空检查 + 错误提示显示 | 验证错误态 UI 样式 |

| **禁止的 JS 用途** | 示例 | 应由谁实现 |
|-------------------|------|-----------|
| **拖拽交互逻辑** | 列宽拖拽 mousedown/move/up、弹窗拖拽移动 | 前端编码（Step 5） |
| **数据联动** | 搜索→表格过滤、排序→重排、分页→请求 | 前端编码（Step 5） |
| **状态管理** | 全局 store、表单双向绑定、乐观锁版本控制 | 前端编码（Step 5） |
| **网络请求模拟** | fetch/mock API、loading 态自动触发 | 前端编码（Step 5） |
| **键盘/手势事件** | Esc 关闭、快捷键、长按菜单 | 前端编码（Step 5） |
| **复杂动画** | 拖拽预览线、骨架屏 shimmer 动画循环 | 前端编码（Step 5） |

**判断标准**：如果一段 JS 的目的是"让人看到某个交互发生后的视觉效果"，且该效果可以用 CSS hover/focus 或简单的 class 切换来近似展示 → **允许**。如果这段 JS 是在实现一个完整的功能模块 → **禁止**，用 `[PRD 交互标注]` 注释替代。

#### 原型必须包含（Do）

| 类别 | 内容 | 说明 |
|------|------|------|
| **页面布局结构** | Sidebar / Header / Content 三段式 | 必须符合 §1 布局系统 |
| **设计 Token 呈现** | 色彩、字体、间距、圆角、阴影的实际效果 | 每个值都来自本规范 §§2-5 |
| **组件形态** | 按钮、表格、弹窗、Badge、分页等 | 必须符合 §6 组件规格 |
| **暗/亮模式切换** | `data-theme` 属性 + CSS 变量 | 两种模式都必须可预览 |
| **基础交互暗示** | hover 态、focus 态、active 态 | CSS `:hover` / `:focus` 即可 |
| **表单字段列表** | 弹窗/表单中的字段名、类型、必填标记 | 必须**严格对齐 PRD 定义** |
| **空状态占位** | EmptyState 组件的展示形态 | 含 CTA 按钮示意 |
| **Tab 结构** | 详情页 Tab 的完整列表（含未实现模块的空占位） | 让人一眼看到全貌 |

#### 原型不包含（Don't）— 用注释标注代替

| 类别 | 示例 | 标注方式 |
|------|------|---------|
| **完整业务逻辑流** | 排序、筛选、分页联动 | `[PRD 交互标注]` 注释 |
| **服务端交互** | API 调用、乐观锁冲突(409) | `[PRD 交互标注]` 注释 |
| **路由守卫** | 归档项目不可编辑 | `[PRD 交互标注]` 注释 |
| **权限控制** | 角色 CRUD 权限矩阵 | 不在原型范围内 |
| **Loading 骨架屏** | shimmer 动画 | 文字说明 + §6.9 规格引用 |
| **复杂表单校验** | 格式校验、唯一性冲突提示 | 字段旁注释说明规则 |
| **键盘/遮罩关闭** | Esc 关闭弹窗、点击遮罩关闭 | `[PRD 交互标注]` 注释 |
| **跨页面导航** | 列表页 → 详情页跳转 | 独立原型不实现导航联动 |

### 11.3 交互标注规范

对于 PRD 已定义但原型不实现的交互行为，使用统一标注格式：

```html
<!-- [PRD 交互标注] F-M1-XX 功能点名称：
     具体行为描述。
     触发条件 / 边界情况 / 错误处理。 -->
```

**标注覆盖清单**（每个原型必须检查）：

- [ ] 搜索行为：回车触发、防抖时间、搜索范围
- [ ] 筛选行为：筛选选项、即时生效 vs 需确认
- [ ] 排序行为：可排序列、默认排序、升/降切换
- [ ] 分页行为：pageSize 选项、URL 参数同步、Loading 态
- [ ] 表单校验：每条字段规则、错误提示位置、唯一性约束
- [ ] 弹窗交互：Esc 关闭、遮罩关闭、提交按钮 Loading 态
- [ ] 危险操作：归档/删除的警告文案（红色强调）、二次确认措辞
- [ ] 空状态：触发条件、CTA 按钮文案和跳转目标
- [ ] 权限/状态限制：归档后按钮置灰、只读字段等
- [ ] 错误处理：版本冲突、网络异常等边界情况的用户反馈

### 11.4 M1 原型自查问题复盘

以下问题在 M1 首批原型中出现，后续模块应避免：

| # | 问题类别 | 具体表现 | 根因 | 防范措施 |
|---|---------|---------|------|---------|
| 1 | **字段与 PRD 不一致** | 创建弹窗用了 `code` 字段，PRD 定义的是 `display_name` | 写原型时凭记忆/直觉填字段，未逐行对照 PRD 表单字段列表 | ✅ **写原型前必须打开对应 PRD 章节，逐字段核对** |
| 2 | **编辑弹窗缺字段** | 缺少 `display_name` 和 `version`（version 是乐观锁关键字段） | 未仔细阅读 PRD 的"可编辑字段"定义 | ✅ 编辑弹窗字段 = PRD 明确列出的可编辑字段全集，不多不少 |
| 3 | **Tab 结构不完整** | 详情页只有 2 个 Tab，PRD 定义了 4 个 | 只做了当前有内容的 Tab，遗漏了后续模块的占位 | ✅ Tab 列表以 PRD 为准，未实现的模块显示空占位态 |
| 4 | **缺少空状态组件** | 列表页无 EmptyState | 只考虑了"有数据"的正常态 | ✅ 每个列表页必须包含空状态（默认隐藏即可） |
| 5 | **Unicode 图标跨平台不一致** | emoji/符号在不同 OS/浏览器渲染差异大 | 图标方案选择不当 | ✅ 使用内联 SVG `<symbol>` + `<use>` 方案（纯 HTML 无依赖） |
| 6 | **暗色模式 shadow token 未重定义** | 暗色下卡片几乎看不出层次 | 复制亮色 token 时遗漏阴影调整 | ✅ 暗色模式必须重新评估所有视觉层级 token（尤其是 shadow） |
| 7 | **Sidebar 缺版本号区域** | 底部空白，不符合 ADP 经典布局 | 参考 ADP 布局时遗漏底部元素 | ✅ 对照 §1.2 布局尺寸规范逐项检查 |
| 8 | **表头无排序示意** | 用户无法感知该列可排序 | 只做了静态展示，忽略了交互暗示需求 | ✅ 可排序列添加静态箭头示意（不需实现排序逻辑） |

### 11.5 原型文件结构模板

每个新模块的原型 HTML 文件应遵循以下头部格式：

```html
<!--
  APM 高保真视觉原型 — [模块名][页面名]
  ============================================
  覆盖功能点：F-Mx-NN（...）
  原型定位：路线 A — 视觉规格原型（Visual Spec Prototype）
  职责范围：页面布局、设计 token 呈现、组件形态、暗/亮模式
  不包含：完整业务逻辑、服务端交互、路由守卫、权限控制

  交互行为标注说明：
  - [PRD 交互标注] 注释标记了 PRD 中定义但原型未实现的关键交互行为
  - 这些行为应在 Step 5 编码阶段由前端开发完整实现
-->
```

### 11.6 原型制作检查清单（Checklist）

开始制作前 □ 制作完成后 □

**制作前准备：**
- [ ] 已阅读对应模块 PRD 的全部功能点详细设计（含页面元素列表、交互行为、业务规则）
- [ ] 已阅读本规范（ui-design-spec.md）相关章节
- [ ] 已参考现有已完成的原型文件作为样式基准

**布局与结构：**
- [ ] 符合三段式布局（Sidebar 220px + Header 48px + Content）
- [ ] Sidebar 包含：Logo 区 + 导航菜单 + 分组标签 + **版本号区域**
- [ ] Header 包含：面包屑 + 主题切换 + 通知 + 用户信息
- [ ] 页面类型判断正确（列表页/详情页/对话框页），使用了对应模板

**内容完整性：**
- [ ] 所有弹窗/表单的字段名、必填标记、placeholder 与 PRD **逐字段一致**
- [ ] 编辑模式 = PRD 规定（行内编辑 vs Dialog，以 PRD 为准）
- [ ] 详情页标题格式 = `display_name (name 小字标注)`（PRD §4.3）
- [ ] 详情页 Tab 列表 = PRD 定义的全部 Tab（未实现的显示空占位）
- [ ] 列表页包含空状态组件（默认隐藏）
- [ ] 可排序列与 PRD 一致（仅 PRD 指定的列头有排序箭头示意）
- [ ] **列表页分页器完整**：总数 + pageSize 选择器(10/20/50/100) + 页码按钮 + 跳页输入（§6.7）

**表格专项（如有表格）：**
- [ ] 表格 `width: auto` + `table-layout: auto`（内容驱动，不强制撑满容器）
- [ ] 每列定义了合理的 `max-width`（参考 §6.3.1 按内容类型选值）
- [ ] 单元格设置了 `overflow:hidden; text-overflow:ellipsis; white-space:nowrap`
- [ ] 可能超长的单元格添加了 `title` 属性（tooltip）
- [ ] 每个 `<th>` 内包含 `.col-resize-handle` 视觉手柄（光标变 col-resize，**无拖拽逻辑**）
- [ ] 表头文字居中（`text-align:center`），操作列数据右对齐

**视觉质量：**
- [ ] 所有颜色值来自 §§2 配色系统（禁止硬编码随意色值）
- [ ] 圆角、间距、字号符合 §§3-5 规范
- [ ] 组件形态符合 §6 组件规格
- [ ] 图标使用 SVG `<symbol>` 方案（禁止 Unicode emoji）
- [ ] 亮色模式和暗色模式均可正常切换预览
- [ ] 暗色模式下卡片阴影足够明显（shadow token 已重定义）

**交互标注：**
- [ ] 文件头部有原型定位声明（§11.5 模板）
- [ ] 所有 PRD 定义但未实现的交互行为均有 `[PRD 交互标注]` 注释
- [ ] 标注覆盖 §11.3 清单中的所有适用项
