## 1. 导航架构与组件结构

### 1.1 组件层级

内置 Agent 不是独立路由页面，而是**全局常驻组件** + **一个独立管理页**：

| 组件 | 形态 | 挂载位置 | 可见性 |
|------|------|---------|--------|
| **Chat 侧栏** | 全局右侧抽屉面板 | App Layout 顶层 | 所有页面可呼出 |
| **@ 上下文菜单** | 弹出式下拉 | Chat 输入框内 | 输入 @ 时出现 |
| **推荐卡片** | 嵌入式卡片 | Chat 消息流内 | Agent 输出时出现 |
| **记忆管理页** | 独立路由页面 | `/settings/memory` | 设置菜单入口 |

### 1.2 路由映射

| 路由 | 页面 | 说明 |
|------|------|------|
| `/settings/memory` | 记忆管理 | 用户浏览/编辑/删除记忆 |

> Chat 侧栏无独立路由，作为全局组件叠加在任何页面上。

### 1.3 侧边栏菜单更新

在**全局层**（非项目层）的系统设置菜单下新增入口：

```
系统设置
  └── AI 记忆管理        ← 新增
```

## 2. 全局交互约定

| 约定编号 | 约定内容 | 适用场景 |
|---------|---------|---------|
| UI-M7-01 | **Chat 面板不遮挡主内容**：打开 Chat 时主内容区宽度收缩（非覆盖），保证用户可同时查看页面和对话 | Chat 侧栏 |
| UI-M7-02 | **流式打字效果**：Agent 回复逐字显示，底部自动滚动；用户手动上滚时暂停自动滚动 | 消息流 |
| UI-M7-03 | **加载状态**：Agent 思考时显示"正在思考…"脉冲动画（三个点），超过 10s 显示"仍在处理…" | 等待回复 |
| UI-M7-04 | **错误消息样式**：LLM/MCP 错误以红色边框 + 警告图标展示，附"重试"按钮 | 错误处理 |
| UI-M7-05 | **Markdown 渲染**：Agent 回复支持完整 Markdown（标题/列表/代码块/表格/加粗） | 消息展示 |
| UI-M7-06 | **快捷键**：`Cmd/Ctrl + Shift + A` 全局切换 Chat 面板开/关 | 全局 |
| UI-M7-07 | **模式指示器**：Chat 顶部始终显示当前模式 Badge（副驾/执行者），点击可切换 | Chat 头部 |

### 3.3 消息流区域

**消息气泡规格**：

| 角色 | 对齐 | 背景色 | 头像 |
|------|------|--------|------|
| user | 右对齐 | `bg-primary/10` | 无（或用户头像） |
| assistant | 左对齐 | `bg-muted` | 🤖 图标 |
| system | 居中 | `bg-transparent text-muted-foreground text-sm` | 无 |

**消息操作**（hover 时显示）：

| 操作 | 适用角色 | 说明 |
|------|---------|------|
| 复制 | assistant | 复制 Markdown 原文到剪贴板 |

> MVP 不支持编辑/删除消息。

### 3.4 输入区域

| 元素 | 规格 | 交互 |
|------|------|------|
| @ 按钮 | 输入框左侧 `@` 图标按钮 | 点击 = 在输入框插入 @ 字符并触发菜单 |
| 输入框 | 多行 textarea，自动增高（最大 5 行） | Enter 发送，Shift+Enter 换行 |
| 发送按钮 | 右侧箭头图标 | 点击发送；输入为空时 disabled |

**输入框 placeholder**：`输入消息，@ 引用页面数据...`

### 3.5 面板尺寸与动画

| 属性 | 值 | 说明 |
|------|-----|------|
| 宽度 | 400px（固定） | 不可 resize（MVP） |
| 打开动画 | 从右侧 slide-in，200ms ease-out | — |
| 关闭动画 | slide-out 到右侧，150ms ease-in | — |
| 主内容区 | 打开时 `margin-right: 400px` 过渡 | 非覆盖式 |

## 4. @ 上下文菜单

### 4.1 触发方式

- 在输入框中键入 `@` 字符
- 或点击输入框左侧的 @ 图标按钮

### 4.2 菜单布局（两级）

**第一级：区域选择**

```
┌─────────────────────────────────┐
│ 🔍 搜索上下文...                │
├─────────────────────────────────┤
│ 📐 领域模型            (12 项) ▶│
│ 🔄 业务流程             (3 项) ▶│
│ 👥 组织与角色           (8 项) ▶│
│ 📦 应用管理             (4 项) ▶│
└─────────────────────────────────┘
```

**第二级：元素选择**（点击区域后展开）

```
┌─────────────────────────────────┐
│ ← 返回   📐 领域模型            │
├─────────────────────────────────┤
│ 🔍 搜索...                      │
├─────────────────────────────────┤
│ □ 实体: 订单 Order              │
│ □ 实体: 订单项 OrderItem        │
│ □ 实体: 客户 Customer           │
│ □ 关系: Order → OrderItem       │
│ □ 领域边界: 交易域              │
└─────────────────────────────────┘
```

### 4.3 交互行为

| 行为 | 说明 |
|------|------|
| 多选 | 第二级支持多选（checkbox），可选多个元素 |
| 搜索过滤 | 两级均支持实时搜索过滤 |
| 确认选择 | 选中后按 Enter 或点击"确认"按钮 |
| 取消 | Esc 关闭菜单，不插入任何内容 |
| 选中展示 | 确认后在输入框上方显示已选 chip（可删除） |

### 4.4 已选上下文 Chip

选中后，输入框上方显示上下文引用 chip：

```
┌────────────────────────────────────────────────┐
│ [📐 实体:Order ✕] [📐 关系:Order→Item ✕]      │  ← chip 行
├────────────────────────────────────────────────┤
│ 帮我看看这两个对象的设计是否合理...    [发送 ➤] │
└────────────────────────────────────────────────┘
```

| 属性 | 规格 |
|------|------|
| 样式 | `bg-secondary rounded-full px-2 py-0.5 text-xs` |
| 内容 | `{area图标} {label}` |
| 删除 | 点击 ✕ 移除该引用 |

## 5. 推荐卡片

### 5.1 卡片布局

```
┌───────────────────────────────────────────────────┐
│ 📋 建立订单领域                                    │  ← 标题
│───────────────────────────────────────────────────│
│ 基于我们的讨论，建议创建以下实体和关系：           │  ← 描述
│                                                   │
│ ☑ 实体：订单 Order（10 个字段）        [展开 ▼]  │  ← 子项
│ ☑ 实体：订单项 OrderItem（6 个字段）   [展开 ▼]  │
│ ☑ 实体：客户 Customer（8 个字段）      [展开 ▼]  │
│ ☑ 关系：Order → OrderItem (composition)          │
│ ☐ 关系：Order → Customer (association)           │  ← 用户取消勾选
│                                                   │
│           [采纳选中项 (4)]    [全部丢弃]           │  ← 操作按钮
└───────────────────────────────────────────────────┘
```

### 5.2 子项展开预览

点击 [展开 ▼] 后显示 Markdown 预览：

```
│ ☑ 实体：订单 Order（10 个字段）        [收起 ▲]  │
│   ┌─────────────────────────────────────────┐    │
│   │ 字段：                                  │    │
│   │ • orderNo: string — 订单编号            │    │
│   │ • status: enum — 订单状态               │    │
│   │ • totalAmount: decimal — 总金额         │    │
│   │ • ...（共 10 个字段）                   │    │
│   └─────────────────────────────────────────┘    │
```

### 5.3 执行中状态

采纳后，子项显示执行进度：

```
│ ✅ 实体：订单 Order（10 个字段）                  │  ← 成功
│ ✅ 实体：订单项 OrderItem（6 个字段）             │  ← 成功
│ ⏳ 实体：客户 Customer（8 个字段）                │  ← 执行中
│ ❌ 关系：Order → OrderItem — 超时失败  [重试]    │  ← 失败
```

### 5.4 采纳后折叠态

全部执行完毕后，卡片折叠为一行：

```
┌───────────────────────────────────────────────────┐
│ ✅ 已采纳 4 项，丢弃 1 项              [展开 ▶]  │
└───────────────────────────────────────────────────┘
```

### 5.5 交互规则

| 规则 | 说明 |
|------|------|
| 依赖联动 | 取消勾选实体 → 自动取消依赖它的关系子项（灰显 + tooltip 说明） |
| 按钮状态 | "采纳选中项 (N)" 中 N = 当前勾选数；N=0 时 disabled |
| 不可逆 | 采纳/丢弃后操作按钮消失，替换为折叠摘要 |
| 失败重试 | 失败子项旁显示 [重试] 按钮，仅重试该子项 |

## 8. 模式切换交互

### 8.1 副驾模式（默认）

- Agent 回复为**文本 + 推荐卡片**
- 卡片等待用户勾选 → 采纳 → 才执行 MCP 写入
- Agent 不会主动修改任何数据

### 8.2 执行者模式

- Agent 回复为**文本 + 执行结果通知**
- Agent 在回复过程中直接调用 MCP 工具
- 执行结果以内联通知形式展示：

```
│ 🤖 好的，我已经为你创建了以下内容：          │
│                                             │
│ ✅ 实体：订单 Order（10 个字段）            │
│ ✅ 实体：订单项 OrderItem（6 个字段）       │
│ ✅ 关系：Order → OrderItem (composition)    │
│                                             │
│ 还需要我继续设计客户模块吗？                │
```

### 8.3 执行者模式 — 高危确认

遇到以下操作时，即使在执行者模式也弹出确认：

| 高危操作 | 确认方式 |
|---------|---------|
| 删除实体/关系 | 内联确认卡片："确定删除实体 Order？此操作不可逆" [确认] [取消] |
| 批量修改（> 5 项） | 内联确认卡片列出所有变更项 |

## 9. 响应式与边界处理

### 9.1 面板状态持久化

| 状态 | 存储位置 | 说明 |
|------|---------|------|
| Chat 面板开/关 | localStorage `apm-chat-open` | 刷新后恢复 |
| 当前会话 ID | localStorage `apm-chat-session` | 刷新后恢复到上次会话 |
| 模式选择 | 跟随 ChatSession.mode（后端） | 以后端为准 |

### 9.2 空状态

| 场景 | 展示 |
|------|------|
| 无会话（首次使用） | 欢迎消息 + 功能引导（见 §3.1 初始消息） |
| 会话无消息 | 同上 |
| 记忆列表为空 | 空状态插图 + "AI 会在对话中自动学习你的偏好" |

### 9.3 网络异常

| 场景 | 处理 |
|------|------|
| SSE 断连 | 消息流底部显示黄色横幅"连接中断，正在重连…"，自动重试 3 次 |
| 重连失败 | 横幅变红"连接失败"，附 [手动重连] 按钮 |
| 发送失败 | 用户消息标记 ⚠️ 发送失败，附 [重试] |

## 10. AI-系统交互规格

> 本节定义 Agent 后端与前端的结构化通信协议（SSE 事件类型）。

### 10.1 SSE 事件类型

| 事件类型 | 数据格式 | 说明 |
|---------|---------|------|
| `message_start` | `{ messageId, role: "assistant" }` | Agent 开始回复 |
| `content_delta` | `{ delta: string }` | 文本增量（逐 token） |
| `card_start` | `{ cardId, title }` | 推荐卡片开始 |
| `card_item` | `{ item: RecommendationItem }` | 卡片子项（逐个推送） |
| `card_end` | `{ cardId }` | 卡片结束 |
| `tool_call` | `{ tool, args, itemId }` | 执行者模式：正在调用 MCP |
| `tool_result` | `{ itemId, status, result }` | MCP 调用结果 |
| `message_end` | `{ messageId, tokenCount }` | 回复结束 |
| `error` | `{ code, message }` | 错误 |

### 10.2 前端消息发送格式

```typescript
// POST /api/agent/chat
interface ChatRequest {
  sessionId: string;
  content: string;              // 用户输入文本
  contextRefs?: ContextRef[];   // @ 引用的上下文快照
}

interface ContextRef {
  area: string;                 // 区域名
  label: string;                // 显示标签
  data: Record<string, any>;    // 结构化数据快照
}
```

### 10.3 推荐卡片采纳请求

```typescript
// POST /api/agent/cards/:cardId/apply
interface ApplyCardRequest {
```
