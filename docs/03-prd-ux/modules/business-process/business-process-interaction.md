### 3.5 主画布

#### 3.5.1 泳道背景层

泳道背景用 DOM div 实现，位于 ReactFlow 画布下层（z-index 更低）。

**泳道配色方案：**

不同泳道拥有不同的背景色，用于视觉上区分泳道区域。配色选用低饱和度柔和色，不喧宾夺主。

| 颜色 | 格子背景 | 标题底色 | 标题文字色 |
|------|----------|----------|------------|
| 蓝 | `bg-blue-50/60` | `bg-blue-100` | `text-blue-800` |
| 翠 | `bg-emerald-50/60` | `bg-emerald-100` | `text-emerald-800` |
| 琥 | `bg-amber-50/60` | `bg-amber-100` | `text-amber-800` |
| 紫 | `bg-violet-50/60` | `bg-violet-100` | `text-violet-800` |
| 玫 | `bg-rose-50/60` | `bg-rose-100` | `text-rose-800` |
| 青 | `bg-cyan-50/60` | `bg-cyan-100` | `text-cyan-800` |

- 按泳道索引循环取色（6色循环）
- 同一 Participant 行内所有格子共享该行的背景色
- 自定义泳道列标题的底色按列索引取色
- 所有泳道标题文字加粗加黑（`font-extrabold` + 对应深色文字色）

**默认泳道：**

- 所有流程图至少有一个默认自定义泳道，默认名称为「活动流程」
- 新建流程时自动创建该泳道，用户可重命名或删除（但删除后如无其他自定义泳道需重新创建）

**Participant 横向排列时：**

```
┌─────────────────────────────────────────────────────────────┐
│ 客户  │                                                    │
│       │  ┌─────────┐        ┌─────────┐                   │
│       │  │ 提交订单 │ ────▶  │ 支付判断 │                   │
│───────┼──┴─────────┴────────┴─────────┴───────────────────│
│ 系统  │                         │        │                 │
│       │                    ┌────┘        └────┐          │
│       │                    ▼                  ▼          │
└─────────────────────────────────────────────────────────────┘
       ↑
       自定义泳道纵向排列（左右）：初始阶段 | 交易阶段 | 完成阶段
```

**节点位置约束：**

- 每个节点必须落在其所属泳道交叉区域内，或在拖拽过程中自动拓展泳道以适应
- 节点拖拽时：
  - 若节点边缘超出当前泳道边界，但节点中心点仍在当前泳道内 → **自动拓展泳道尺寸**以容纳节点（留 8px 边距）
  - 若节点中心点超出当前 Participant 泳道，进入另一 Participant 泳道 → 弹出确认 Dialog（见 §4）
  - 若仅跨越了 Custom 泳道边界 → 自动更新 `customLaneIndex`，无弹窗
- 拓展规则：
  - 自定义泳道（纵向列）：节点右侧超出时自动增加列宽
  - 角色泳道（横向行）：节点底部超出时自动增加行高

**泳道分隔线 resize：**

- 鼠标悬停在泳道分隔线上，光标变为 resize 样式，分隔线高亮（蓝色半透明）
  - Custom 泳道垂直分隔线：`ew-resize`（↔），拖拽调整列宽
  - Participant 泳道水平分隔线：`ns-resize`（↕），拖拽调整行高
- 拖拽分隔线实时调整相邻泳道尺寸，释放后自动保存 layout
- **最小尺寸约束**：泳道缩小后的尺寸必须能包含该泳道内所有节点（节点 8px 边距），不允许缩小到无法容纳节点的程度
- 绝对最小尺寸限制为 100px（无节点时的底线）

**画布边界限制：**

- 画布不是无限平移的空白区域，其边界由泳道内容决定
- 用户拖动画布时，当触及内容的上下左右边界时停止，不允许滚动到空白区域
- 内容边界 = 所有 Custom 泳道总宽度 + 表头（32px） × 所有 Participant 泳道总行高 + 表头（32px）

**角色泳道 sticky 效果：**

- 左侧 Participant 泳道行标题（竖排标签）在垂直滚动时保持可见
- 当向下拖动画布时，行标题始终展示在最左侧，不被节点遮挡
- 行标题层 z-index 高于 ReactFlow 节点，确保始终在最前
- 标签文字随缩放比例等比例变化

#### 3.5.3 节点组件

**ActionNode（活动节点）：**

```
┌─────────────────────────────┐
│ [Role] 提交订单        [✏] │  ← 右上角编辑按钮（hover 显示）
│ submit_order                 │
│ ────────────────────────────│
│ 输入: userId, productId, qty │  ← inputs 摘要（来自 actionRef）
│ 输出: orderId, status        │  ← outputs 摘要
│ 工具: —                      │  ← tool 类型（如有）
└─────────────────────────────┘
```

**DecisionNode（决策节点）：**

```
         Decision
        支付结果判断
       pay_result_check
            ◇
           / \\          ← 菱形外形（clip-path），内部文字水平展示
          /   \\
         ◇─────◇        ← 4 个固定 Handle（上下左右端点）
```

- **外形**：菱形（CSS `clip-path: polygon(50% 0%, 100% 50%, 50% 100%, 0% 50%)`），尺寸 120×120px
- **文字**：水平展示，不被 clip-path 裁剪，多行截断（2 行）
- **Handle**：固定 4 个（上/左为 target，右/下为 source），不随分支数量变化
- **边框色**：默认 `amber-300`，选中 `amber-500`，错误 `red-400 dashed`

**节点选中状态：**
- 边框变为主题色（蓝色）
- 显示拖拽手柄（四角）
- 显示删除按钮（右上角，与编辑按钮并排）

**节点 hover 状态：**
- 显示编辑按钮（右上角）
- 显示连接点（上下左右四个方向的圆点）

#### 3.5.4 边组件

```
        条件: amount > 100
    ┌────────────────────────┐
    │                        │
    ▼                        ▼
┌─────────┐            ┌─────────┐
│ 支付判断 │ ────────▶  │ 支付处理 │
└─────────┘   orderId  └─────────┘
              ──────▶
```

**边的路径规范：**
- 采用**正交路径（Orthogonal Path）**，连线由水平线段和垂直线段组成，拐角为 **90° 直角**
- 不使用贝塞尔曲线（Bezier）
- ReactFlow 实现：`getSmoothStepPath`（`borderRadius: 0`）

**箭头标记：**
- 连线指向 target 节点的一端必须显示**箭头标记（MarkerEnd）**
- 默认颜色 `gray-400`，选中/高亮 `blue-500`，错误 `red-400`
- 箭头大小 `8px`

**重合边跳线（Bridge）：**
- 当多条边在画布上路径重合时，后创建的边在重合处绘制**跳线拱形**（半圆弧形凸起，类似电路图中的 wire jump）
- 跳线半径 `6px`，颜色与边线一致
- 目的：避免视觉重叠导致无法区分多条独立连线

**边显示元素：**
- 带箭头的正交连线
- 条件表达式（如果有）显示在连线上方
- 数据映射标签（如果有）显示在连线下方

**边选中状态：**
- 连线变为主题色（蓝色）
- 显示删除按钮（连线中点）

### 3.6 左侧节点池

可折叠面板，提供节点模板拖拽到画布：

```
┌───────────────┐
│ 节点池      [─]│
├───────────────┤
│               │
│ ┌───────────┐ │
│ │ [Action]  │ │  ← 可拖拽
│ │  活动节点  │ │
│ └───────────┘ │
│               │
│ ┌───────────┐ │
│ │[Decision] │ │  ← 可拖拽
│ │  决策节点  │ │
│ └───────────┘ │
│               │
└───────────────┘
```

**拖拽行为：**
1. 从节点池拖拽节点模板到画布
2. 释放时，如果落在泳道交叉区域内：
   - 创建新节点（调用 API）
   - 节点自动落入对应 participantLane + customLane
   - 弹出属性面板，要求选择 holder 和 actionRef/decisionRef
3. 如果释放位置不在任何泳道内：
   - 吸附到最近的泳道交叉区域

### 3.8 画边交互

**创建边：**
1. 鼠标悬停在源节点上，显示连接点（圆点）
2. 从源节点的连接点拖拽出连线
3. 拖拽到目标节点的连接点释放
4. 如果**源节点是 DecisionNode** 且已绑定 `decisionRef`：
   - 系统查询该 Decision 的分支定义（branches）
   - 弹出「选择分支」Dialog，列出所有分支名和条件表达式
   - 用户选择一个分支后，创建边并将分支名写入 `config.sourceBranch`
5. 如果源节点是 ActionNode 或未绑定 decisionRef 的 DecisionNode：
   - 直接创建边，不弹出分支选择 Dialog

```
┌─────────────────────────────────────┐

│   status == "success"               │
│                                     │

│   status == "failed"                │
│                                     │
│        [取消]  [确认]               │
└─────────────────────────────────────┘
```

**删除边：**
- 选中边后，点击中点的删除按钮，或按 Delete 键

### 3.9 保存与验证交互

**自动保存策略（验证前置）：**

所有变更（节点位置、增删改、属性修改）均采用自动保存：

```
用户变更 → 防抖 2 秒 → 调用 validate API → 结果?
  ├── ✓ 验证通过 → 执行保存 → 显示"已保存"
  └── ✗ 验证失败 → 取消保存 → 显示错误 Banner + 高亮问题项
```

**保存状态指示器：**

| 状态 | 显示 | 说明 |
|------|------|------|
| 已保存 | `Text` (sm, muted, green) "✓ 已保存" | 所有变更已同步 |
| 保存中 | `Text` (sm, muted) "⏳ 保存中..." | 验证/保存请求进行中 |
| 验证失败 | `Text` (sm, destructive) "✗ 验证失败，未保存" | 验证未通过，数据未同步 |
| 保存失败 | `Text` (sm, destructive) "✗ 保存失败" | 网络/服务端错误 |

**验证错误展示：**

验证失败时，画布顶部显示持久性红色 Banner（不自动消失）：

```
┌─────────────────────────────────────────────────────────────┐
│ ✗ 验证失败，未保存                                          │
│ • 「node_003」孤立节点（无入边也无出边）                   │
│ • 「node_001 → node_002 → node_001」循环检测               │
│        [查看详情]  [强制保存]                                │
└─────────────────────────────────────────────────────────────┘
```

- 点击问题项自动定位到对应节点/边
- 问题节点/边高亮红色虚线边框
- 「强制保存」按钮：允许用户在知晓风险的情况下跳过验证强制保存（用于未完成的设计草稿）

## 4. 跨泳道拖拽

### 4.1 跨 Participant 泳道拖拽

当用户将节点从 Participant A 的泳道拖拽到 Participant B 的泳道时：

**步骤 1：拖拽释放**
- 节点释放在新泳道交叉区域
- 系统检测到 `participantLaneIndex` 发生变化

**步骤 2：弹出确认 Dialog**

```
┌─────────────────────────────────────┐
│ 变更参与者                    [×]   │
├─────────────────────────────────────┤
│ 是否将节点从「客户」变更为「系统」？  │
│                                     │
│ ⚠️ 变更后需要重新选择 Action/Decision │
│                                     │
│        [取消]  [确认变更]            │
└─────────────────────────────────────┘
```

**选项说明：**

| 按钮 | 行为 |
|------|------|
| 取消 | 节点弹回原泳道边界内，不保存变更 |
| 确认变更 | 更新节点 `holderType`/`holderId`，清空 `actionRef`/`decisionRef`，保存布局位置变更 |

**变更后处理：**
- 节点成功迁移到新 Participant 泳道
- 节点的 actionRef/decisionRef 被清空，需要在属性面板重新选择
- Toast 提示「参与者已变更，请在属性面板重新选择 Action/Decision」

### 4.2 跨 Custom 泳道拖拽

仅改变 `customLaneIndex`，不触发任何确认 Dialog。

```
节点从「初始阶段」拖到「交易阶段」
→ 仅更新 customLaneIndex
→ 自动保存 layout
→ 无确认 Dialog
```

### 5.3 调整泳道顺序

**Participant 泳道：**
- 在下拉菜单中拖拽排序（上下移动）
- 或点击"▲"/"▼"按钮调整顺序

**自定义泳道：**
- 在"管理泳道"Dialog 中拖拽排序（左右移动）

### 5.4 调整泳道尺寸

**交互方式：**

1. 鼠标悬停在泳道分隔线上（Participant 泳道之间或 Custom 泳道之间）
2. 光标变为 resize 样式：
   - 横向排列时：Participant 分隔线为 `ns-resize`（↕），Custom 分隔线为 `ew-resize`（↔）
   - 纵向排列时：Participant 分隔线为 `ew-resize`（↔），Custom 分隔线为 `ns-resize`（↕）
3. 悬停时分隔线高亮显示（蓝色半透明背景 `bg-blue-400/30`）
4. 拖拽时实时调整泳道尺寸，提供即时视觉反馈
5. 释放鼠标后自动保存 layout 到后端

**约束：**
- 最小泳道尺寸：80px
- 分隔线热区宽度/高度：4px（居中于边界）
- 拖拽时阻止事件冒泡，避免触发 ReactFlow 画布平移

### 5.5 泳道对调

点击"泳道对调 ⇄"按钮：
1. 切换 `orientation`（horizontal ↔ vertical）
2. 所有节点坐标 x↔y 转换
3. 画布重新渲染
4. 自动保存 layout

## 8. 错误处理

| 场景 | 处理方式 |
|------|---------|
| API 请求失败 | Toast 提示错误信息，操作按钮恢复可用状态 |
| 节点创建失败 | 节点从画布移除（回滚），显示错误 Toast |
| 边创建失败（如形成环） | 边从画布移除，显示错误 Toast "此连接将形成循环" |
| 保存失败 | 保存按钮变为"保存失败，重试"，数据不丢失（本地缓存） |
| 验证失败 | 画布顶部显示错误 Banner，问题项高亮 |
| 跨泳道嫁接失败 | Dialog 保持打开，显示错误信息，用户可选择"仅移动节点" |
