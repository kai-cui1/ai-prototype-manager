### 3.3 视图切换交互

| 操作 | 行为 |
|------|------|
| 点击「卡片」按钮 | 列表区域切换为卡片网格；视图偏好写入 localStorage key `apm-app-view-mode`；当前筛选/分页/搜索状态不变 |
| 点击「表格」按钮 | 列表区域切换为表格；视图偏好写入 localStorage；当前状态不变 |
| 刷新页面 | 从 localStorage 读取视图偏好，恢复上次选择；无记录时默认卡片视图 |
| 视图切换时加载态 | 卡片 → 表格：卡片区域 fade-out → 表格 fade-in（150ms）；反之亦然 |

### 3.4 交互流程

**主流程（浏览应用列表）：**

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 进入应用管理页 `/p/:projectId/applications` | 从 localStorage 读取视图偏好；渲染页面，发起 `GET /api/v1/projects/:projectId/applications` |
| 2 | 等待加载 | 当前视图模式显示对应 Skeleton |
| 3 | 数据返回 | 按当前视图渲染列表，默认 sort_order ASC + updatedAt DESC |
| 4 | 输入搜索关键词 | 300ms 防抖后重新请求，携带 `search` 参数，分页重置到第 1 页 |
| 5 | 切换类型筛选 | 立即重新请求，携带 `type` 参数，分页重置到第 1 页 |
| 6 | 切换视图模式 | 纯前端切换，不发 API 请求 |
| 7 | 点击表头排序（表格视图） | 重新请求，携带 `sort` + `order` 参数 |
| 8 | 翻页/切换每页条数 | 重新请求，携带 `page` / `pageSize` 参数 |

### 3.5 分页功能

**分页信息栏布局**：

```
共 12 个应用  [◀ 上一页] 第 1/2 页 [下一页 ▶]  [每页 20 条 ▼]
```

**元素清单**：

| 元素 | 组件 | 说明 |
|------|------|------|
| 总数提示 | `Text` (muted) | "共 N 个应用"；无数据时显示"共 0 个应用" |
| 上一页按钮 | `Button` (ghost, sm) | 图标 `ChevronLeft`；第 1 页时 disabled |
| 页码提示 | `Text` (sm) | "第 {current}/{total} 页"；仅 1 页时仍显示"第 1/1 页" |
| 下一页按钮 | `Button` (ghost, sm) | 图标 `ChevronRight`；最后一页时 disabled |
| 每页条数选择器 | `Select` (sm) | 选项：10 / 20 / 50 / 100；默认 20；切换后分页重置到第 1 页 |

**分页交互规则**：

| 场景 | 行为 |
|------|------|
| 点击「上一页」 | 请求 page-1；按钮 disabled 时不响应 |
| 点击「下一页」 | 请求 page+1；按钮 disabled 时不响应 |
| 切换每页条数 | 请求 page=1, pageSize=新值 |
| 搜索/筛选变更 | 分页重置到第 1 页 |
| 数据为空 | 分页栏隐藏（空状态区域已包含引导） |
| 仅 1 页数据 | 上一页/下一页均 disabled，但仍显示总数和页码 |

### 4.3 交互细节

| 场景 | 行为 |
|------|------|
| 打开 Dialog | type 默认未选中，name/display_name 为空；创建按钮禁用 |
| 选中 type | type 选项高亮，name 和 display_name 的占位符更新为对应 type 的示例 |
| 点击「创建」 | 前端完整校验 → 失败则高亮错误字段；通过则按钮 loading，发起请求 |
| name 格式错误（失焦） | 字段下方显示红色错误文案"仅允许小写字母、数字、连字符，且以字母开头" |
| 返回 409（name 冲突） | name 字段下方红色错误"该名称已被使用，请更换"；Dialog 不关闭 |
| 返回 201 成功 | Dialog 关闭 → Toast "应用「{display_name}」已创建" → 列表刷新显示新卡片 |
| 点击遮罩或 Esc | Dialog 关闭，表单数据清空（UI-M1-09） |

| 应用标识符（name） | `Input` | 必填；`^[a-z][a-z0-9-]*$`；1-50 字符 | 预填充当前值；修改时校验唯一性（排除自身） |
| 显示名称（display_name） | `Input` | 必填；1-100 字符 | 预填充当前值 |
| 描述（description） | `Textarea` | 可选；最大 500 字符 | 预填充当前值 |
| 取消按钮 | `Button` (ghost) | — | 关闭 Dialog，不保存 |
| 保存按钮 | `Button` (primary) | — | 触发校验 → 调用 PUT API |

### 5.3 交互细节

| 场景 | 行为 |
|------|------|
| 打开 Dialog | type 显示为只读 Badge；其余字段预填充当前值 |
| 修改 name（失焦） | 前端校验格式 + 发起唯一性预检（输入停止 500ms 后） |
| 返回 409（name 冲突） | name 字段下方红色错误"该名称已被使用"；停留 Dialog |
| 返回 200 成功 | Dialog 关闭 → Toast "已保存" → 对应卡片数据更新 |
| 未做任何修改点保存 | 直接关闭 Dialog，不发请求 |

## 6. 删除应用

### 6.1 交互流程

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 点击应用卡片上的 🗑 按钮 | 弹出 AlertDialog |
| 2 | AlertDialog 内容（无引用时） | 标题："删除「{display_name}」？" / 正文："此操作不可撤销。" / 按钮：「取消」+「确认删除」（红色） |
| 2' | AlertDialog 内容（有引用时，仅 type=service） | 标题："无法删除「{display_name}」" / 正文："该应用正在被 {N} 个流程节点引用，无法删除。请先修改或移除相关流程节点。" / 按钮：「我知道了」 |
| 3 | 点击「确认删除」 | 按钮 loading；发起 `DELETE /api/v1/applications/:id` |
| 4a | 成功 | 卡片从列表移除；Toast "已删除" |
| 4b | 返回 409 IN_USE | 切换 AlertDialog 内容为有引用提示（见步骤 2'） |
| 点击「取消」或 Esc | — | AlertDialog 关闭 |

### 6.2 删除场景判定

| 应用 type | 引用检查 | 删除行为 |
|-----------|---------|---------|
| service | 检查 process_nodes 中 holder_type='service' AND holder_id=该id | 有引用 → 阻止；无引用 → 允许 |
| web/wxapp/android/ios/pc/api | 无需检查（当前不会被引用） | 直接允许 |

> 注：前端在点击删除按钮时**不预判**引用状态，统一先弹出确认弹窗；由后端 DELETE 接口返回 409 时再切换为引用提示。避免前端多做一次查询请求。

## 7. 项目概览页更新

> 路由：`/p/:projectId`

项目概览页的「模块概要」卡片网格区域需新增「应用管理」卡片。

### 7.1 概要卡片设计

> **决策（2026-06-02）**：应用管理卡片采用「总数 + 类型分布」统计方式，整张卡片可点击跳转，与仅显示单一数字的其他统计卡片区分，体现应用多平台分布的特点。

**视觉布局**：
```
┌──────────────────────────────────────────┐
│  [Layers图标]  3 个应用           cursor:pointer │
│                Web×1  API×1  服务×1          │
└──────────────────────────────────────────┘
```

**元素规格**：

| 元素 | 组件 | 规格 | 说明 |
|------|------|------|------|
| 图标容器 | `div` | 44×44px，圆角 10px，粉色背景 | 与侧边栏菜单图标一致（`Layers`，#fff0f6 / #c41d7f） |
| 总数文字 | `Text` | 22px / 600 | "N 个应用"；N=0 时显示"暂无应用" |
| 标签行 | `Text` | 12px / text-tertiary | 标签格式：`{类型名}×{数量}`，仅展示数量 > 0 的类型，各标签间以空格分隔；最多显示 4 个，超出省略 |
| 卡片区域 | `Card`（整张） | hover：`cursor-pointer` + 轻微 shadow 加深 | 整张卡片可点击，跳转到 `/p/:projectId/applications` |

**类型标签显示名称**（与 Badge 一致）：

| type | 标签名 |
|------|--------|
| web | Web |
| wxapp | 小程序 |
| android | Android |
| ios | iOS |
| pc | PC |
| api | API |
| service | 服务 |

**状态变体**：
- 无应用（total=0）：总数文字改为"暂无应用"（text-tertiary），不显示类型标签行，保留整张可点击跳转
- 有应用（total>0）：显示总数 + 非零类型标签

### 7.2 概要卡片排序

概要卡片区域排列（响应式网格，1/2/3 列）：

| 位置 | 卡片 | 统计 |
|------|------|------|
| 1 | 应用管理 | N 个应用 + 类型分布标签 |
| 2 | 领域模型 | N 个实体 |
| 3 | 业务流程 | N 个流程 |
| 4 | 公司/组织 | N 个公司 |
| 5 | 部门 | N 个部门 |
| 6 | 角色 | N 个角色 |
| 7 | 外部实体 | N 个 |

### 7.3 Summary 接口更新

项目详情的 summary 接口（`GET /api/v1/projects/:id/summary`）新增返回字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| applicationCount | integer | COUNT(applications WHERE project_id)，所有类型总数 |
| applicationTypeBreakdown | Record\<string, number\> | 按 type 分组计数，key 为 type 值（仅包含数量 > 0 的类型）；无应用时返回 `{}` |

**applicationTypeBreakdown 示例**：
```json
{
  "applicationCount": 3,
  "applicationTypeBreakdown": {
    "web": 1,
    "api": 1,
    "service": 1
  }
}
```

**后端实现要点**：在现有 7 个并行 COUNT 查询基础上，增加一个 `GROUP BY type` 查询，两者均在 `Promise.all` 中并行执行，无额外 RTT 损耗。
