## 1. 导航架构与页面结构

### 1.1 路由映射

## 2. 全局交互约定

| 约定编号 | 约定内容 | 适用场景 |
|---------|---------|---------|
| UI-M1-01 | **确认弹窗**：所有破坏性操作（归档/恢复/删除）使用 `AlertDialog`（非普通 Dialog）；确认按钮使用危险色（红色 / `destructive` variant），取消按钮使用次要样式 | 归档、恢复、删除操作 |
| UI-M1-02 | **Loading 态**：所有异步操作触发按钮在请求期间显示 `spinner` + 禁用态，防止重复提交 | 所有 POST/PUT/DELETE/PATCH |
| UI-M1-03 | **乐观更新**：列表新建/删除成功后立即更新本地 UI，同时后台 revalidate；失败时回滚并 Toast 提示 | 列表页新建/删除 |
| UI-M1-04 | **空状态引导**：所有列表在无数据时显示空状态插画 + 友好提示文案 + 「新建」按钮，不允许纯空白 | 所有列表页 |
| UI-M1-05 | **防抖搜索**：搜索框输入后 300ms 防抖再发起请求，清空时自动重置 | 所有搜索框 |
| UI-M1-06 | **Esc 取消**：所有 Dialog / AlertDialog / Sheet 支持 Esc 键关闭，等同于点击「取消」 | 所有弹窗 |
| UI-M1-07 | **归档视觉区分**：归档状态用灰色 `Badge`（text: "已归档"）标识，列表行降低透明度；归档项目的所有写操作按钮隐藏 | 项目列表 / 概览页 |
| UI-M1-08 | **Toast 反馈**：写操作成功后弹出 Toast（右上角，3s 自动消失）；文案格式："XXX 已创建" / "XXX 已归档" / "XXX 已删除" | 所有写操作 |
| UI-M1-09 | **表单重置**：Dialog 每次打开时都是全空（或预填充）的干净状态，关闭后重置表单数据 | 所有新建/编辑 Dialog |

|------|------|------|------|
| 顶部操作栏 | 搜索框 | `Input` + 搜索图标 | 对 `name` 字段 ILIKE 模糊搜索；300ms 防抖 |
| 顶部操作栏 | 状态筛选器 | `Tabs` 或 `ToggleGroup` | 三态：全部 / 活跃 / 已归档；默认选"全部" |
| 顶部操作栏 | 新建项目按钮 | `Button` (primary) | 点击打开「新建项目」Dialog |
| 卡片列表 | 项目卡片 | `Card` | 3 列网格（宽屏）/ 2 列（中屏）/ 1 列（窄屏） |
| 项目卡片 | 项目显示名称 | `CardTitle` | `display_name`，大字体 |
| 项目卡片 | 项目标识符 | `Text` (muted) | `name`，小字，灰色 |
| 项目卡片 | 状态 Badge | `Badge` | `active` → 绿色"活跃"；`archived` → 灰色"已归档" |
| 项目卡片 | 摘要统计 | `Text` (small) | "N 实体 / M 流程 / O 公司"，来自 summary 字段 |
| 项目卡片 | 更新时间 | `Text` (muted, small) | 相对时间（"2天前"）；hover 显示精确时间 |
| 项目卡片 | 进入项目按钮 | `Button` (outline/ghost) | 活跃项目显示"进入项目"；归档项目显示"查看详情" |
| 项目卡片 | 操作菜单（hover） | `DropdownMenu` | hover 卡片右上角出现 `⋮` 按钮，展开：编辑基本信息 / 归档（或恢复） |
| 底部 | 分页器 | `Pagination` | 每页 20 张卡片，可切换 10/20/50/100 |
| 空状态 | 空状态区域 | `EmptyState` | "还没有项目，点击「新建项目」开始创建" + 新建按钮 |
| 加载状态 | Skeleton | `Skeleton` | 加载时显示卡片骨架屏 |

### 3.3 交互流程

**主流程（浏览项目）：**

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 进入系统 `/` | 渲染 Dashboard，发起 `GET /api/v1/projects`（含 summary 内嵌字段） |
| 2 | 等待加载 | 显示卡片 Skeleton（保持卡片网格结构感） |
| 3 | 数据返回 | 渲染项目卡片，显示名称/状态/统计/更新时间 |
| 4 | 输入搜索关键词 | 300ms 防抖后重新请求，携带 `search` 参数，卡片列表更新 |
| 5 | 切换状态筛选 | 立即重新请求，携带 `status` 参数 |
| 6 | 切换分页 | 请求对应页 |

**激活项目流程：**

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 点击活跃项目卡片「进入项目」 | 1. 调用 `setActiveProject(projectId)`，写入 localStorage；2. 路由跳转 `/p/:projectId`；3. 侧边栏菜单切换为项目上下文菜单 |
| 2 | 点击归档项目卡片「查看详情」 | 路由跳转 `/p/:projectId`，但页面显示为只读模式（无编辑入口） |

**归档项目（列表内）：**

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | hover 卡片，点击 `⋮`，选择"归档" | 弹出 AlertDialog："确认归档「{display_name}」？归档后不可编辑，数据保留。" |
| 2 | 点击「确认归档」（红色按钮） | 按钮 loading；调用 `PATCH /api/v1/projects/:id/status`，Body: `{status:'archived', version}` |
| 3a | 成功 | 卡片 Badge 更新为"已归档"，操作菜单换成"恢复"；Toast："已归档" |
| 3b | 乐观锁冲突（409） | Toast 错误提示，刷新该卡片数据 |
| 4 | 点击「取消」或 Esc | AlertDialog 关闭，无操作 |

### 3.4 新建项目 Dialog（F-M1-02）

**Dialog 布局：**

```
┌─────────────────────────────────┐
│ 新建项目                      × │
├─────────────────────────────────┤
│ 项目标识符 *                     │
│ [                            ]  │
│ 仅允许小写字母、数字和连字符，   │
│ 如：ev-charging-station         │
│                                  │
│ 显示名称 *                       │
│ [                            ]  │
│                                  │
│ 项目描述                         │
│ [                            ]  │
│ [                            ]  │
│                                  │
├─────────────────────────────────┤
│               [取消]  [创建项目] │
└─────────────────────────────────┘
```

**元素清单：**

| 元素 | 组件 | 校验规则 | 说明 |
|------|------|---------|------|
| 项目标识符（name） | `Input` | 必填；`^[a-z][a-z0-9-]*$`；1-50 字符 | 失焦时前端校验；占位符"ev-charging-station" |
| 显示名称（display_name） | `Input` | 必填；1-100 字符 | 占位符"换电站管理系统" |
| 项目描述（description） | `Textarea` | 可选；最大 500 字符 | 自适应高度；字符计数显示 |
| 取消按钮 | `Button` (ghost) | — | 关闭 Dialog，不保存 |
| 创建项目按钮 | `Button` (primary) | — | 触发表单完整校验 → 调用 API |

**交互细节：**

| 场景 | 行为 |
|------|------|
| 点击「创建项目」 | 前端完整校验 → 失败则高亮错误字段；通过则按钮 loading，发起请求 |
| name 格式错误（实时） | 失焦后字段下方显示红色错误文案"仅允许小写字母、数字、连字符，且以字母开头" |
| 返回 409（name 冲突） | name 字段下方显示红色错误"该标识符已被使用，请更换"；Dialog 不关闭 |
| 返回 201 成功 | Dialog 关闭 → Toast "项目「{display_name}」已创建" → 路由跳转到 `/p/:projectId` |
| 点击遮罩或 Esc | Dialog 关闭，表单数据清空 |

### 4.3 编辑基本信息（F-M1-04）

编辑采用**行内编辑模式**：点击「编辑」按钮后，基本信息卡片的字段变为可编辑输入框。

**编辑态布局变化：**

```
基本信息  [保存]  [取消]          ← 操作按钮出现在区域标题右侧
─────────────────────────────────
显示名称: [换电站管理系统      ]
标识符:   [ev-charging-station ]
描述:     [                    ]
          [                    ]
创建时间: 2026-05-01 10:00       ← 只读，不可编辑
更新时间: 2026-05-26 09:30       ← 只读，不可编辑
版本:     v3                     ← 只读
```

**交互细节：**

| 场景 | 行为 |
|------|------|
| 点击「编辑」 | 基本信息卡片字段变为 Input/Textarea；出现「保存」「取消」按钮；页头「编辑」按钮隐藏 |
| 输入 name（失焦） | 前端实时校验格式；格式错误时字段下方红字提示 |
| 按 Esc | 等同于点击「取消」，还原所有字段到进入编辑前的快照值 |
| 单行字段按 Enter | 等同于点击「保存」（description 多行文本域除外） |
| 点击「保存」 | 前端完整校验 → 发起 `PUT /api/v1/projects/:id`（携带 version）|
| 保存成功（200） | 字段恢复只读展示，显示更新后的值；`updated_at` 和 `version` 刷新；Toast "已保存" |
| name 冲突（409 NAME_CONFLICT） | name 字段下红字"该标识符已被使用"；停留编辑态 |
| 乐观锁冲突（409 VERSION_CONFLICT） | AlertDialog 提示"数据已被修改，请刷新后重试"；确认后刷新页面 |
| 归档项目访问 | 编辑按钮隐藏，所有字段只读 |

### 4.4 归档 / 恢复项目（F-M1-05）

**归档流程：**

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 点击「归档项目」（红色按钮） | 弹出 AlertDialog |
| 2 | AlertDialog 内容 | 标题："归档「{display_name}」？" / 正文："归档后该项目将不可编辑，数据保留。可随时恢复。" / 按钮：「取消」+「确认归档」（红色） |
| 3 | 点击「确认归档」 | 按钮 loading；发起 `PATCH /api/v1/projects/:id/status`，Body: `{status:'archived', version}` |
| 4a | 成功 | 页面状态更新：Badge 变灰色"已归档"，所有编辑入口隐藏，「归档」按钮替换为「恢复项目」；Toast "已归档" |
| 4b | 乐观锁冲突（409） | Toast 错误提示，保持原状 |

**恢复流程：**

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 点击「恢复项目」 | 弹出 AlertDialog："恢复「{display_name}」为活跃状态？" |
| 2 | 点击「确认恢复」 | 发起 `PATCH`，Body: `{status:'active', version}` |
| 3 | 成功 | Badge 恢复绿色，编辑入口显现，「恢复」按钮替换为「归档项目」；Toast "已恢复" |

## 9. 项目层路由守卫

| 场景 | 处理 |
|------|------|
| 未激活项目时访问 `/p/...` | 重定向到 Dashboard（`/`），并 Toast 提示"请先选择一个项目" |
| localStorage 中 `activeProjectId` 对应的项目已归档 | 正常恢复上下文，但页面显示"已归档"状态，写操作入口隐藏 |
| localStorage 中 `activeProjectId` 对应的项目不存在（已删除） | 清除 localStorage，重定向到 Dashboard，Toast 提示"项目不存在或已被删除" |
| 刷新页面 | 从 localStorage 读取 `activeProjectId`，自动恢复项目上下文 |
